## 1. 问题陈述：库表面是现代化的「未认领半区」（r32 审查结论）

### 1.1 审查实测（全项目扫描——2026-09-12，Task 53-a）

| 模式类 | 定义域实测 | 判定 |
|---|---|---|
| `?` 后缀谓词 | 注册名 18 件（`null?`/`pair?`/`int?`/…/`str-contains?`）；引导语料自铸 41 个含 `?` 私有名（`err?`/`contains?`/`is-keyword?`——**后者已是 `is-`+`?` 杂交**）；21 个测试文件 240 处引用 | ❌ Lisp 家族约定，现代化无 owner |
| `->` 中缀转换 | 注册名 3 件（`string->symbol`/`symbol->string`/`str->pos-chars`）；引导语料自铸 9 个（`num->str`/`chars->str`/`list->pairs`/`datum->value`…） | ❌ 同上 |
| `!` 后缀变异 | 库表面 0 件（`set!` 是核心形式非内置）——**无债**；关键字面归 E5 窗口 | ✅（关键字协调见 §6.3） |
| 历史包袱访问器 | `car`/`cdr`（1959 IBM 704 寄存器缩写——Contents of Address/Decrement Register）×379 处引导语料 + `last-pair` | ❌ 命名精确性最低类 |
| 扁平命名空间 | 57 名全局单空间：`str-`×11 + `list-`×2 + `char-`×2 前缀补丁式分域；无模块限定引用面 | ❌ 前缀 ≠ 命名空间（前缀是约定、命名空间是机制） |
| 行为模式遗留 | `str-index-of` 未找到 `-1` 哨兵（pre-Option 时代）；`member`/`assoc` 命中返子表/未命中 `false`（真值多态）；`read-line` 运行时忽略多余实参（元数纪律缺口） | ⚠️ 见 §4 行为契约 |

**核心发现（对「为什么现在做」的回答）**：库表面债随每个新内置**线性累积**——Stage 2 库化生长（[09 §2](./09-stdlib.md)「完整库化生长是 Stage 2 切换信号」）即将放量；每延迟一轮，迁移面（注册表 × HM 签名表 × 门控表 × 引导语料 × 测试 × 文档）等比放大。这正是用户指令「不然在之后阶段中也是需要大量时间和精力去重构」的量化形态。

### 1.2 为什么「内部已定方向、表面未跟进」是不一致状态

设计文档集已在内部语法侧**冻结 2026 演进方向**（v1.1 措辞修正——r32 版「已完成现代化」失实）：原则 29（命名行为导向）/30（类型安全优于命名安全）/31（表面-内部语法分离）+ [01 §8.3](./01-core-forms.md) 迁移映射 + E5 委员会裁定（r18）——注意这套裁定的载荷是**结构级重构设计**（`Define` 脱糖 / `VarRef` de Bruijn 索引化 / `Module` 层级迁移 / `SetBang→Perform(State)` 效应化——[21 §5](./21-capability-architecture.md) 六类迁移分类学归档），**重命名只是其中最浅的一类**（`App→Apply` 等 M-R 类）；实施绑定 E5 Stage 3 一次性窗口（自举 parity 链保护——§6.2）。但用户可见面——**学习者第一眼看到的 57 个名字**——连方向都未冻结（r32 前无 owner）。两个半区的成熟度差：内部侧「方向已冻结、实施有窗口、重构有分类学」；表面侧（r32 前）「无方向、无映射、无债务登记」。这不是「风格偏好」问题而是**架构一致性问题**（原则 29 的适用域缺了半区）：标点后缀约定（`?`/`!`/`->`）是**前类型系统时代的补偿机制**——在名字里编码「返回布尔」「有副作用」「是转换」这些本应由类型系统承载的信息。kerf 已拥有 HM 推断（r29 判定面）+ 效应处理器（r25 Perform/Handle）+ 能力门控（r8）——**现代机制已就位，表面命名不应继续补偿不存在的能力缺口**。

## 2. 2026 前沿对照（跨语言实证——知识搜索精华）

| 维度 | Lisp 家族（Racket/Scheme） | 2026 前沿共识（Rust/Swift/Kotlin/Clojure） | kerf 裁定 |
|---|---|---|---|
| 布尔谓词 | `?` 后缀（`null?`） | 前缀 `is`：Swift `isEmpty`/`isDigit`、Kotlin `isX`、Rust `is_empty`（Swift API 设计指南「clarity at the point of use」+「避免缩写」） | **R2：`is-` 前缀** |
| 动词谓词/关系 | 一律 `?` | 裸动词：Rust/Swift `contains`/`starts_with`；关系词裸形（`eq`/`==`） | **R3：裸动词/关系词** |
| 转换 | `X->Y` 中缀（C 风格指针转型的语法残留） | 方向词：Rust `to_`/`into_`（所有权语义区分）/`from_`（目标侧构造）；Kotlin `toX` | **R4：`X-to-Y` + 模块内 `to-X`/`from-Y` 双向** |
| 变异标记 | `!` 后缀（Scheme） | 类型/效应承载：Koka、OCaml 5 效应系统（效果入类型而非名字） | **R5：库面零 `!` 新铸；效应纪律承载** |
| 序对访问器 | `car`/`cdr`（1959 硬件寄存器） | `head`/`tail`（ML/Haskell 系）或 `first`/`rest`（Clojure） | **`head`/`tail`**（ML 血统——与既有文档 [01 §7.2](./01-core-forms.md) 评注一致） |
| 标准库组织 | 扁平全局 + `cl:` 前缀补丁（CL） | 命名空间限定：Clojure `clojure.string` → `str/join`（Lisp 家族内部的现代答案）；Julia `String.length` | **R1 配套：`kerf/<模块>` + `/` 限定引用（§5）** |
| 缩写 | `str`/`num`/`char` 随处 | 全词（Swift 指南「avoid abbreviations」；Rust 标准库全词方法名） | **R1：全词——`str-` → `string-`** |

## 3. 表面命名规范 v1（六条规则 R1-R6）

> **适用域**：用户可见库表面（内置函数名、标准库模块名、导出名）。**不适用**：核心形式关键字（`lambda`/`set!`/… ——核心冻结 + E5 Stage 3 窗口，见 §6.3）；内部 ADT 变体名（已由原则 29-31 + E5 治理）；运算符符号族（R6 冻结）。

- **R1 描述性全词**：名称使用完整单词（`string` 非 `str`）、动词-宾语语序（`string-contains`）、拒绝缩写与历史致敬（`car`→`head`）。依据：Swift API 设计指南「clarity at the point of use」+ 原则 29（命名行为导向）在库表面的延伸。
- **R2 状态/类型谓词 = `is-` 前缀**：`is-nil`/`is-pair`/`is-int`/`is-string`/…。依据：§2 对照表——`?` 后缀是 Lisp 家族标记，`is` 前缀是 2026 跨范式共识（Swift/Kotlin/Rust）；谓词性同时由返回类型承载（HM Bool），名字不再需要标点补偿。**迁移后标识符字符域收敛为字母/数字/连字符**——可 grep、可索引、无「标识符内含操作符字符」的词法复杂度。
- **R3 动词谓词与关系词 = 裸形**：`contains`/`starts-with`/`ends-with`（动作询问，非状态测试）；关系词 `eq`（恒等关系，区别于链式值相等 `=`——见 B5）。依据：Rust/Swift `contains`/`starts_with` 同型；动作与状态测试语义不同，不应同用 `is-`。
- **R4 转换 = `to`/`from` 方向词**：扁平过渡形 `X-to-Y`（`string-to-symbol`）；命名空间终态**双向双家**——源侧模块导出 `to-X`（`string/to-symbol`）、目标侧模块导出 `from-Y`（`symbol/from-string`）。依据：Rust `to_`/`from_` 方向语义学（源侧视角 `to`、目标侧视角 `from`）；`->` 中缀是 C 指针转型时代的语法残留，且破坏 R2 的字符域收敛。
- **R5 库面零 `!` 新铸**：新内置/新库函数一律不以 `!` 后缀标记变异；变异副作用由效应纪律（Perform/Handle——r25 已在位）与后续类型面承载。关键字 `set!` 的更名（`set`/`assign` 候选见 [01 §7.2](./01-core-forms.md)）**绑定 E5 Stage 3 一次性切换窗口**（核心形式面，非本规范适用域——协调见 §6.3）。
- **R6 符号运算符族冻结**：`+`/`-`/`*`/`/`/`mod`/`=`/`<`/`>`/`<=`/`>=` 维持符号形态。依据：数学表面是跨语言通用语（非「Lisp 家族遗留」——Scheme 与 Rust 共享此面）；仅命名族收敛，运算符族不动。

**规则判定的最小闭包**：任何新表面名提交前过五问——① 全词？② 布尔返回 → `is-` 还是动词裸形？③ 转换 → `to/from` 方向词？④ 有副作用 → 效应面声明了吗（而非 `!` 名字标记）？⑤ 模块家定了吗（§5）？

## 4. 行为契约现代化（B1-B5）

> **迁移不变量（本规范的载荷纪律）**：**别名层零语义变更**（v0.5 纯改名——现代名 ≡ 旧名行为逐字节 parity，测试锚定）；**契约层零兼容承诺**（v0.6 命名空间模块定义现代契约——B1/B2/B3 变更落位于此，新名新契约、旧名旧契约并存至移除）。改名与改行为**永不混步**——一步一验，杜绝双名双行为的隐性分叉。

| # | 遗留行为 | 现代契约 | 落位 | 依据 |
|---|---|---|---|---|
| B1 | `str-index-of` 未找到返回 `-1`（pre-Option 哨兵值——哨兵与合法值域重叠：`-1` 既是「未找到」也是合法索引的邻域负数） | `string/index-of` 未找到返回 `nil`（nil-as-absence 与语言值域一致——`read-int` EOF→nil 已是先例） | v0.6 | 哨兵值是错误码时代遗产；Option/nil 二值化是 2026 共识 |
| B2 | `member`/`assoc` 命中返回子表/点对、未命中返回 `false`（真值多态——用 `false` 佯装「无结果」） | `list/member` 命中返回子表、未命中返回 `nil`；返回类型单一化（表-or-nil，不再与 bool 交叠） | v0.6 | 真值多态是动态语言早期宽松产物；类型域纯净化配合 HM |
| B3 | `read-line` 运行时忽略多余实参（builtins.rs 实测注记——**r40/R4 修正：历史注记已过期**，当前底层严格 0 参[FS-4 修复面覆盖运行时——`read-line 需要 0 个参数` 错误路径在位]） | `io/read-line` 严格 0 参（多余实参 = 运行时错误，与其他内置元数纪律对齐） | v0.6 | 元数纪律一致性（**B3 = 纯测试锚零代码变更**——r40 M2 实测确认底层已对齐，契约面由 m2_b3_contract_read_line_strict_arity case 锚定） |
| B4 | `(+)`→0、`(*)`→1、`(- x)`→取负 | **保留**（显式裁定：数学恒等元是原则性行为，非遗留债） | 不变 | 群恒等元语义（unit/identity）；Clojure/Racket 同型 |
| B5 | `eq?` 恰 2 参不可链；`=` 链式值相等 | **保留**（恒等关系 vs 值相等的语义区分是原则性的） | 不变 | `eq`（恒等）与 `=`（值）是两个关系；链式性是值相等族的性质 |

## 5. 组织结构：命名空间层（v0.6 方向概要——机制层设计见 22）

> **v1.1 分工声明**：本节持**方向概要与模块树**（谁家有什么名字）；**机制层完整设计**（五层命名层级 N0-N4、解析优先序 R-N1、遮蔽许可表 R-N2、限定名不回落 R-N3、权限矩阵、冲突三类裁定、保留域与版本化接口位）由 [22-命名空间设计](./22-namespace-design.md) 承载——**v0.6 批次 M 的实施输入以 22 为准**（本节是 22 的导览层非替代）。两文件的分层理由：20 是表面规范（名字/行为/组织），22 是机制规范（存在/解析/授权）——层间耦合点唯一（§5.3 能力对齐），已在 21 §4.3 精确化。

### 5.1 限定名语法（Reader 面）

`/` 作为**标识符内部的命名空间分隔符**：`string/append` = 命名空间 `string` 的 `append`。**词法规则**（Clojure 同型裁定）：独立 `/`（前后无标识符字符）维持除法运算符；`/` 仅在标识符内部作分隔符。Reader 变更 = 标识符字符域增 `/`（中间位）——词法层零语义原则不破坏（[02 §6 不变式 3](./02-syntax-model.md)）。

### 5.4 导入形式与 prelude

- **限定导入**：`(import kerf-string as str)` → 模块内 `str/append`（模块别名局部绑定——命名冲突显式化）
- **非限定导入**：`(import kerf-string)` → 本地注入 `append`/`length`/…（冲突 = 显式错误——沿用 kerf-prelude 的「显式失败优于静默遮蔽」语义，[09 §2](./09-stdlib.md) v6.2 注记同型）
- **prelude 定位重锚**：`kerf-prelude`（`bootstrap/preamble.krf`）= **便利 + 兼容层**——自有五件（`map`/`filter`/`foldl`/`foldr`/`for-each`——已是现代名）+ 再导出高频核心名（`head`/`tail`/`nth`/`drop`/`is-*` 全集）的非限定形。旧名（`car` 等）**不经 prelude 再导出**——旧名只存在于全局注册表面（v0.5 过渡），不进入任何推荐路径。

## 6. 与既有裁定的协调（不冲突证明）

### 6.1 核心冻结（原则 9）——不受影响

57 内置名是**库表面**（driver 注册的 δ 函数表，[09 §1](./09-stdlib.md)「语言核心零内置」），非核心形式。更名/加别名 = `register_globals` 表操作，CoreExpr 零接触。**核心冻结原则反而构成本规范的前提**：正因内置不在核心，库表面才可独立于核心冻结演进。

### 6.2 E5 裁定（REJECT-STANDALONE，r18）——适用域划分而非冲突

E5「语义化命名 REJECT-STANDALONE、绑定 E1-E4 全落地后 Stage 3 一次性迁移」的**论证载荷**是：核心 ADT 半迁移会造成自举 parity 链的**中间态破坏**（编译器源码半新半旧、双形态互译）。库表面别名层**不存在此载荷**：别名是纯增量（旧名不动、新名同语义注册），自举链、parity 测试、758 现有断言**零接触**。故本规范不违反 E5，而是把它精确化为适用域划分：**内部 ADT + 关键字面 = E5 一次性窗口（Stage 3）；库表面 = 别名渐进（v0.5 起）**。

### 6.3 关键字面（`lambda`/`set!`/`begin`/…）——显式划出

22 个 Keyword（[02 §1](./02-syntax-model.md) 叶级 48 计数）的更名属**核心形式关键字面**：绑定 E5 Stage 3 窗口，与本规范的 v0.5/v0.6 批次**无耦合**。协调点唯一：Stage 3 移除轮（旧内置名移除 + 关键字切换）**同窗执行**，一次性清算「1970 表面」，避免两轮 breaking。

> **r43 / E5 S2 腿实施注记（22 §12 D19-D33 重筛终选）**：关键字三件已切换 `lambda→fn`/`set!→assign`/`begin→do`（**否决原 set/seq 候选**——名空间经济判据：set 集合构造生态占用 / seq Clojure 序列生态占用；单源 = [22 §12](./22-namespace-design.md) + e5-plan §4.2 否决记录）；旧形 `lambda`/`set!`/`begin` 引用 → E0021 携新名指引（接管豁免同 S1 口径）；`fn`/`assign`/`do` 即刻入 E0020 禁绑面（25 名计数不变）。

### 6.4 HM 签名表与能力门控——三方同步契约

`BUILTIN_SIGS`（**r38 双名同步后 83 项**——56 基础 + 27 别名同签名，[09 §2](./09-stdlib.md)——HM 判定面 R8 消费）与 R9 门控名表（E0006 验证面）必须与 `register_globals` **三方同步**（既有守护 `builtin_sigs_subset_of_registered` 漂移守卫扩展为三方）。v0.5 别名层实施清单：① 注册表面 57→84（27 新别名 + 24 不变 + 4 引导私有跳过 + 6 I/O 不变名——实注册 57+27=84）；② `BUILTIN_SIGS` 双名同步；③ 门控表同步（`print`/`read-line` 等 6 件的别名 = 原名——I/O 族无新名，门控表零变更，**实测核对**）；④ parity 测试组（每别名 1 case 行为等价断言）。**r38 实施兑现 ✅（59-a / 批次 L 交付）**：①-④ 全落地（84 注册 + 83 签名[守卫锚逐项相等] + 门控零变更实测[READ_GATED/WRITE_GATED 六名 ⊆ 注册 + 别名零交集] + 27 parity case + 三方守卫两测试——`builtins.rs` `BUILTIN_ALIASES` 表/`builtin_aliases_closed_and_parity_typed`/`builtin_gating_names_subset_of_registered`；stdlib_tests 27 parity 组 + `alias_parity_group_covers_all_27` 闭合守卫）。

## 9. 引导语料与测试面纪律

1. **新语料一律现代名**（批次 L 起）：`bootstrap/*.krf` 新增代码、examples 新件、测试新 case——R1-R6 生效（旧名仅存量面）。

3. **parity 锚点**：`bootstrap_compiler_tests` / `stdlib_tests` 增别名组——`(car x)` ≡ `(head x)` 逐字节同码（同一 builtin 分派即天然 parity；断言双名同结果 + 同 Span 行为）。
4. **漂移守卫扩展**：`builtin_sigs_subset_of_registered` → 三方（注册 ⊇ 签名 ⊆ 门控）+ 别名闭合（每别名必有 parity case——防注册了没测、测了没注册）。
