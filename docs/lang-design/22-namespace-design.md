## 1. 问题陈述：命名空间作为「机制」的设计缺位

**r32 审查实测**（本文件的驱动源）：20 §5 已交付——限定名语法（`/` 分隔符 + Clojure 同型词法裁定）、七件模块树、导入形式、prelude 重锚。**但以下机制层问题在 20 中无 owner**（v0.6 批次 M 实施时每一项都必须回答）：

| 缺位问题 | 为什么不能等到实施时再答 | 知识搜索实证（q1/q5） |
|---|---|---|
| 非限定名的解析优先序 | import 注入名与全局名与局部名的竞争规则影响**每个表达式**的语义 | Tratt《Designing Sane Scoping Rules》：作用域规则是语言最深的语义承诺之一 |
| 遮蔽的许可面 | 哪些遮蔽合法、哪些报错、哪些警告——三者分界是设计裁定非实现细节 | langdev.se 遮蔽讨论：禁止遮蔽「会约束远处的语言设计」 |
| 限定名是否回落全局 | `string/append` 未命中时查不查全局 `append`——决定限定名的语义纯度 | Reddit 模块设计：模块名 = 文件系统式前缀，命名空间碰撞**禁止**而非回落 |
| 授权与可见性的传播关系 | import 是否携带能力（[21 §4.2 红线 1](./21-capability-architecture.md) 已裁**不传播**——需要命名侧的机制配合） | Austral：模块系统与安全模型绑定但分层 |
| 冲突的三类处理 | 非限定 import 冲突/双模块同名导出/全局与模块名竞争——各自独立裁定 | Clojure：require/refer 冲突显式报错；`refer :exclude` 逃逸阀 |
| 保留域与开放性 | 用户模块能否叫 `kerf/string`——标准库演进面的保护边界 | Clojure 风格指南：`project.module` 组织约定 |

**缺位的量化风险**（与 20 §1.1「线性累积」论证同构）：命名规则影响每行程序——v0.6 实施时临时裁定 = 每条裁定都是无审计的暗设计；本文件把全部裁定前置到设计层（§2-§7），批次 M 只做「实现规则表 + 测试锚」的机械作业。

## 2. 五层命名层级（Name Universe N0-N4）

### 2.1 层级总图与四要素

```
N4 保留字层    lambda if set! begin define module require import perform handle …
    （Reader 期消费——语法上下文标记，非变量，永远先于名字解析）
N3 局部绑定层  lambda 参数 / let 系 / define 局部形（module 体内）
    （作用域 = 词法嵌套，内向外查找）
N2 模块层      module 的 export 面 / import 注入面 / 限定名可见面
    （名字的组织与授予——「谁家的名字」）
N1 全局注册层  register_globals 的 57 内置（v0.4 现状：单空间扁平）
    （v0.6 后收缩为：运算符族 R6 冻结名 + 门控按 require 面注入 + 旧名兼容注册）
N0 符号宇宙    SymbolTable intern——名字的**存在性**层
    （str→symbol id 的全局唯一化，与可见性无关——「名字存在」≠「名字可见」）
```

| 层 | 定位 | 边界 | 职责（不变量） | 正交契约 |
|---|---|---|---|---|
| **N0 符号宇宙** | 名字存在性：intern 域 | 不做任何可见性/解析决策 | 同一拼写 ⟺ 同一 symbol id（intern 幂等）；TD-002 符号值语义的载体 | 上层全部经 N0 取 id——N0 变更（如 interning 策略）零语义影响 |
| **N1 全局注册层** | 名字的默认可见面：无声明即可引用的名字 | 不做作用域（全局=程序级）；v0.6 后**不再是库组织的合法路径**（新库名必须入 N2——20 §7 迁移纪律） | δ 函数表（`register_globals`）= 事实源；门控按 require 面裁剪（fail-closed） | 与 N2 竞争时 N3 胜出（§3.2 优先序） |
| **N2 模块层** | 名字的组织与授予：命名空间的机制层 | 不做语义（模块体语义=`Module` 原语职责——[21 §5.2](./21-capability-architecture.md) M-L 行）；不做授权（L3 专职——§5） | export 面显式声明；import 注入显式声明；**默认不可见**（opt-in——kerf-prelude r15 先例：无 import 报未绑定） | 授权门对齐不变量（[21 §4.3](./21-capability-architecture.md) + 本文 §5） |
| **N3 局部绑定层** | 名字的作用域：词法单元 | 不做跨模块可见性（局部名永不逃逸模块） | 内向外查找序；同名 define 显式报错（v6.2 既有裁定）；lambda/let 绑定遮蔽外层**合法** | 与宏卫生交互（§4.3——ScopeSet 保证展开插入的绑定不误捕） |
| **N4 保留字层** | 语法上下文标记 | 不是值、不可引用、不可遮蔽（**三件套全编译期执行——r41 / D10 E0020**：绑定禁令封死遮蔽路径[Stx 源码面 + CoreExpr 展开产物面双层]；绑定禁后值位引用恒未绑定[fail-closed]；quote 位豁免是 N0 数据非 N4 值） | Reader 先行分词——关键字恒定形态（[02 §1](./02-syntax-model.md) 词法架构） | E5 Stage 3 关键字切换窗口（`set!` 更名等）是 N4 的唯一变更通道 |

### 2.2 与 Clojure/Rust 的层级对照（知识搜索 q5/q6 实证）

| 维度 | Clojure | Rust | kerf（本设计） |
|---|---|---|---|
| 命名分层 | ns（=N2）+ var（=N3 动态查找）+ special form（=N4） | mod 树（N2 嵌套）+ item/let（N3）+ 关键字/宏（N4） | **五层显式分层**——N0 独立成层（存在性/可见性分离是 kerf 特色：symbol intern 与解析解耦使宏展开期的「同名异义」可判定） |
| 嵌套 | ns 名用 `.` 分段（`clojure.string`），ns 本身不嵌套 | mod 可任意嵌套 + 路径 `::` | 模块**不嵌套**（一层 `kerf/<域>`——[20 §5.2](./20-surface-conventions.md) 模块树扁平）；嵌套语义由域分层承载（21 §3.1 依赖单向图）——**拒绝深嵌套**（matklad 笔记：模块深度是认知成本；Clojure 风格指南同向） |
| 可见性 | public var / `^:private`（二元） | pub / pub(crate) / pub(self) / pub(in path)（谱系） | **export 面白名单制**（默认不可见，export 才导出）——比 Clojure 的默认 public 更收紧（fail-closed 一致性）；**不引入 Rust 谱系**（Stage 2 无 crate 级封闭单元——净空载设计，Stage 3 若出现编译单元封闭需求再评估） |

## 3. 解析规则与遮蔽语义（规则表 R-N1 至 R-N8）

### 3.1 非限定名解析序（R-N1）

```
解析 <name>（非限定）:
  1. N3 内向外：let 系 → lambda 参数 → module 体 define 面
  2. N2 import 注入面（module 头声明的非限定导入）
  3. N1 全局注册层（含门控按 require 面注入的门控名）
  4. 全部未命中 → E0xxx 未绑定变量错误（携带查过的层——诊断三段式）
```

**裁定依据**：①与 kerf-prelude r15 既有行为一致（opt-in 注入 + 未绑定显式失败）；②「内层优先」是词法作用域 60 年共识（Tratt：Converge 同型）；③N2 在 N1 前——import 是**显式局部决策**，应胜过全局默认（显式优于隐式——原则「显式失败优于静默遮蔽」的解析面延伸）。

### 3.2 遮蔽许可表（R-N2——三分界裁定）

| 遮蔽形态 | 裁定 | 依据 |
|---|---|---|
| N3 遮蔽 N1（`(lambda (append) …)` 局部名遮全局 `append`） | **合法**（无警告） | langdev 共识：禁止遮蔽约束远处设计（如宏生成的绑定名）；词法单元的完整性 > 全局名的独占性 |
| N3 遮蔽 N2 注入名 | **合法 + W 级警告**（弃用警告族 18 §6 增行——20 §7 批次 M 既有） | import 是显式意图，遮蔽它多半是命名事故（可恢复但值得提示） |
| N3 同层重定义（同名 lambda 参数/嵌套 let 同名） | **合法**（内层胜——标准词法） | 同上 Tratt 依据 |
| N3 define 与外层 define 同名（module 体内） | **错误**（E0xxx 重复定义——09 v6.2 既有裁定「显式报重复定义」维持） | 既有契约不破坏（r15 prelude 行为锚） |
| N2 非限定 import 与 N3 注入冲突（两模块导出同名） | **错误**（显式冲突——[20 §5.4](./20-surface-conventions.md) 既有裁定：冲突 = 显式错误） | Clojure refer 冲突同型；逃生阀 = 限定导入（R-N5） |
| N4 被任何层遮蔽 | **不可能**（Reader 期先消费——`lambda` 不会成为变量名） | 02 词法架构（关键字表先于标识符判定） |

### 3.3 限定名解析（R-N3——不回落裁定）

```
解析 <module>/<name>（限定）:
  1. 拆分：命名空间段 + 本地名（`string/append` → ns=string, name=append）
  2. 仅查 N2 该命名空间 export 面的本地名
  3. 未命中 → E0xxx「string 不导出 <name>」错误
  【禁止】任何回落（不查全局、不查其他模块、不查局部）
```

**不回落裁定**（q1 Reddit 实证：「模块名 = 文件系统式前缀，碰撞禁止而非回落」）：限定名的语义纯度是命名空间机制的存在理由——回落会把 `string/append` 退化成「全局 append 的别名」（前缀 ≠ 命名空间的 20 §1.1 批判重演）。**代价**：打错模块名报「不导出」而非「未绑定」——诊断按 R-N3 第 3 步精确指向模块面（诊断增益 > 回落便利）。

### 3.4 限定名的词法域（R-N4——20 §5.1 的机制面重申）

标识符字符域增 `/`（中间位，Clojure 同型）：独立 `/` = 除法运算符（前后无标识符字符）；`str/append` = 单一标识符 token（Reader 不拆分——解析期才按 R-N3 拆）。词法层零语义原则（[02 §6 不变式 3](./02-syntax-model.md)）不破坏：`/` 的词法角色 = 标识符内字符，语义角色 = 解析期命名空间分隔（词法/解析分离维持）。

### 3.5 导入形式与别名（R-N5——20 §5.4 的规则化）

| 形式 | 语义 | 冲突处理 |
|---|---|---|
| `(import kerf-string)` 非限定 | 注入 export 面全部本地名到 N2 注入面 | 与其他注入面同名 → 显式错误（§3.2 R-N2 第五行） |
| `(import kerf-string as str)` 限定别名 | 模块内 `str/append` 形态引用（别名是**局部绑定**——N3 语义位） | 别名与局部变量同名 → N3 同层规则（内层胜）；别名与另一别名同名 → 重复定义错误 |
| （隐式）全程序 N1 门控注入 | 门控名按 `require` 面注册（R-N1 第 3 步） | 与 N3 冲突按 R-N2 第一行（合法遮蔽） |

**别名是局部绑定**（精确裁定）：`str` 别名不是全局命名空间（`str/append` 在别模块不可用）——它登记在 N3（局部层），遮蔽规则按 N3 语义走。这与 Clojure `:as` 别名（ns 级）不同：kerf 模块即编译单元（[21 §5.2](./21-capability-architecture.md) Module 卡），别名作用域=模块体（编译单元级——比 Clojure 的 ns 级粗一级，比全局细一级）。

### 3.6 prelude 定位（R-N6——20 §5.4 重锚的规则化）

`kerf-prelude` = N2 普通模块（无特权）：它的「特殊性」只是**内容**（自有五件 + 高频再导出）而非**机制**（注入仍需显式 import）。旧名不经 prelude 再导出（20 既有裁定维持）。**规则推论**：任何模块都可行 prelude 之事（再导出组合）——再导出是 N2 的通用能力（模块可 export 其 import 的名字——组合库的构建基元；Clojure `:refer-clojure`/`(:require … :refer …)` 同型）。

### 3.7 运算符族的层归属（R-N7）

`+`/`-`/`=`/`<` 等 R6 冻结名：**N1 永驻**（不迁移 `kerf/core`——20 §8 映射表「`core` 不导出（全局运算符）」行的机制解释）：数学表面是零依赖最小骨架（OCaml core library 同型定位——q8 实证），若经 import 才可见则**任何程序先付 import 税**——与「零依赖最小骨架」矛盾。运算符是 N1 的**合法永驻者**（唯一类——v0.6 后 N1 新增名仅限运算符族扩展，如 Stage 3 位运算）。

### 3.8 符号宇宙的解析豁免（R-N8）

N0 不参与解析序：`'sym` 引用的符号值**不查任何层**（quote 语义 = 名字即值——[21 §5.3](./21-capability-architecture.md) Const 行的 M-L 前史）。这是「存在性/可见性分离」的收益实例：宏模板里的 `'append` 与变量 `append` 是**两个宇宙的对象**（symbol 值 vs 绑定），零干涉。

## 4. 宏卫生与命名空间的交互（E3 裁定的机制面）

### 4.1 ScopeSet 与五层的协作

[01 §7.3 E3 裁定](./01-core-forms.md)：展开层命名制**永久保持**（ScopeSet 卫生机制载体不可牺牲）。在五层坐标系：ScopeSet 是 **N3 的编译期加强**——展开插入的绑定携带 scope 标记，与程序手写绑定区分（防误捕获）。**协作规则**：①宏生成的**非限定**名走 R-N1 全序（卫生保证它解析到「调用点可见的名字」而非「定义点可见的名字」——这正是卫生的定义）；②宏生成的**限定**名走 R-N3（卫生对限定名透明——`string/append` 无捕获问题，模块面是全局单义的）；③宏内 `gensym` 名 = N3 卫生绑定（N0 intern 但 N3 不可见——私有名机制）。

### 4.2 相位分离的命名面（Phase 0/1 的层归属）

宏系统运行在 Phase 1：宏定义模块的 import 面**独立于**程序模块（Phase 1 命名宇宙与 Phase 0 分离——[02 §2](./02-syntax-model.md) 相位架构既有）。**规则推论**：`import` 在宏体与程序体的解析面不同（宏体的 `str/append` 查宏模块的 import 声明）。v0.6 实施注意：Reader（reader.krf）的自举语料是 Phase 1 消费者——其私有名（`err?` 等 41 件）属引导语料内部 N3，**永不进入**用户 N2（20 §6.5 既有纪律重申）。

**相位授权面注记（v1.1 新增——[21 §4.5](./21-capability-architecture.md) 裁定的命名面接线）**：Phase 1 命名宇宙的独立性同时是**授权面的独立性**——宏体 import 面只授予名字可见性，与授权零涉（Phase 1 = 纯符号变换零授权面；P1→P0 唯一通道 = 宏产生代码）。命名轴与相位轴在授权面的交格 = 空（[21 §2.5](./21-capability-architecture.md) L×N×P 矩阵相位轴交互行）——三轴正交在权限维度的可审计形态。

### 5.2 授权传播的命名面红线（与 21 §4.2 三红线对账）

- **红线 1（import ≠ 授权）命名面表述**：`import kerf-io` 后 N2 注入面含 `io/print` **名字**；无 `(require io write)` 时门控面**未注册**——R-N1 第 3 步查 N1 失败 → E0006（名字可见但不可调用——**双门分立的可观测形态**）。测试锚：批次 M case（§8 表 R1 行）。
- **红线 2（授权零语义）**：矩阵每行的授权变更（收紧/放宽）不触碰 export 面（可见性）——两门独立变化。
- **红线 3（缺省拒绝）**：矩阵未列 = 未授权 = 门控面不含（非「调用时报错」而是「名字不存在于运行面」——E0006 指向 require 声明缺失）。

### 5.3 令牌态无命名空间面的架构说明

FFI 授权（r30）**没有** N2 投影——`External` 值是**持有物**（capability 原教义形态：能力=对象引用），不是名字。这是三态模型（21 §4.1）在命名坐标系的镜像：纯度态（无门）/声明态（双门：N2 可见性 + N1 门控面）/令牌态（零门：值直持）。**推论**：命名空间机制是**声明态专属基础设施**——`kerf/net` 的 N2 面（模块可见性）服务 API 组织，socket 令牌面服务资源持有，两轨并行（§5.1 net 行的双层授权）。

## 7. 开放性、保留域与版本化（演进面）

- **保留域**：`kerf/` 前缀 = 标准库专属（用户模块不得以 `kerf/` 开头——Reader 层登记保留前缀，违例 = E0xxx）。依据：标准库演进不受用户命名空间挤占（Clojure `clojure.*` 同型——q6 实证）；**不设其他保留域**（用户空间全开放——最小保留原则）。
- **单层不嵌套**：模块名 = `<owner>/<domain>` 单层（v0.6 七件即 `kerf/<域>`）。**拒绝嵌套**裁定（§2.2 对照依据）：域依赖由 21 §3.1 单向图承载（架构层），不由名字层级模拟（名字深度 ≠ 架构深度——嵌套是前命名空间时代的模块模拟术）。
- **版本化（接口位锁定）**：`@` 版本语法**不引入**（Stage 2 零消费面）；接口语义位锁定 = 版本化若引入（Stage 3+ 包管理窗口——13 §3.3.8），形态为 `kerf/string@2`（`@` 与 `/` 同为标识符中间位字符——词法域对称扩展）；**语义承诺**：同名模块跨版本是**两个命名空间**（`kerf/string@1` 与 `@2` 零回落——R-N3 不回落裁定的时间维推广）。
- **新标准库模块准入**：增行流程 = [21 §3.1](./21-capability-architecture.md) 域四要素卡 + 本文件 §5.1 矩阵增行 + [20 §3](./20-surface-conventions.md) R1-R6 命名检查 + 18 §6 术语登记——四表联动（防「加了模块没加矩阵」的漂移——20 §9.4 三方守卫的扩展方向）。
