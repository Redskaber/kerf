## 1. 术语定锚：「能力」三义消歧（本文第一个交付物）

| 术语 | 定义 | 唯一 owner 文件 | 反例（禁用形态） |
|---|---|---|---|
| **工程能力**（Engineering Capability） | 构建编译器所需的技术能力（Token 流/图 IR/GC/VM/LSP…三层分类：必须实现/接口预留/完全推迟） | [13-能力矩阵](./13-capability-matrix.md) §1 | 不用于描述语言运行时行为 |
| **语言能力**（Language Capability） | 语言程序运行时的能力域（值域/控制/效应/授权——本文 §2 四层） | **本文** §2 | 不用于描述编译器构建技术 |
| **授权**（Authority） | 安全学术语——程序获得执行某类副作用操作的许可（`require io read` 门控/FFI 线性令牌——ocap 模型的 kerf 形态） | **本文** §4（模型层）+ [13 §3.1.3](./13-capability-matrix.md)（接口层） | 不与「语言能力」互换（授权是四层中的 L3，不是全部） |

**消歧理由**（知识搜索 q2 实证——ocaps 教程：「能力是 OCAP 的原语，如同对象之于 OOP、函数之于 FP」）：对象能力模型（object-capability model）中 capability 特指**可转移的操作权利**；kerf 的 `require io` 正是这个语义（r8 门控 + r25 IoFamily + r30 FFI 令牌三级演进）。把「编译器要不要 GC」也叫「能力」把安全语义稀释了。三义拆净后，§5.3 类段落（20 文件）的「能力族」一词获得精确所指 = **授权族**。

## 2. 语言能力四层正交架构（L0-L3）

### 2.1 四层总图

```
L3 授权层（Authority）    require io read|write · FFI External 令牌 · net/process（Stage 3 预留）
      ▲ 只决定「能不能进入」，不改语义
L2 效应层（Effects）      Perform / Handle · State 语义映射（D5）· continuation（线性唯一）
      ▲ 把副作用从控制流剥离为可拦截的操作
L1 控制层（Control）      Lambda / App / If / VarRef / Literal / SetBang / Begin / Define / Module
      ▲ 组合计算的全部规则（相位分离、卫生宏、TCO）
L0 值域层（Data）         数值塔（Int/Float）· 序对/表 · 字符串（码点序）· 符号 · Bool · nil · External
```

**判层规则**（一个语言特性属于哪层——唯一归属，禁止跨层登记）：问两个问题——①它改变「数据长什么样」吗（是→L0）；②它改变「副作用如何发生」吗（是→L2；纯组合规则→L1；许可语义→L3）。**每层一张四要素卡**：

### 2.2 四要素卡（每层定位·边界·职责·正交）

| 层 | 定位（解决什么问题） | 边界（不解决什么——负空间） | 职责（拥有的决策与不变量） | 正交契约（与邻层的接口） |
|---|---|---|---|---|
| **L0 值域** | 「数据是什么」——值的构造、判别、相等与全序 | 不定义数据的**变换操作**（`reverse`/`index-of` 是库能力域 §3 的事）；不定义值的**传递许可**（L3） | 数值塔（Int×Int→Int 溢出检查/Float 提升/`mod` 拒浮点）、序对与表的形状约定（nil 终结）、字符串码点序（TD-011）、`eq`（恒等）与 `=`（值相等）的分界（B5）、Boxing（TD-010 装箱） | 对 L1 只暴露 Value 域；L2 continuation 快照**引用**值但不重定义值语义（M5 帧根集=引用语义）；L3 FFI 令牌是 L0 的 External 值 |
| **L1 控制** | 「计算怎么组合」——从变量引用到程序相位 | 不定义副作用（引用未绑定/调用的效应由 L2 承载）；不做数据判别（谓词是库域） | 11 语义原语的归约规则（§5 四要素卡）、相位分离（Phase 0/1）、卫生宏（ScopeSet——E3 裁定展开层命名制**永久保持**）、TCO（与效应正交——D8 已验证）、de Bruijn（IR 层 Stage 3——E3 分层裁定） | 只消费 L0 值、只发射 L2 效应；**层间交换律检验（§2.3 判据 J1）** |
| **L2 效应** | 「计算与外界怎么交互」——副作用是一等可拦截操作 | 不定义交互的**许可**（Perform State 不需要授权；门控内置调用需要——许可在 L3）；不做控制流组合（handler 体仍是 L1 程序） | Perform/Handle 语义（浅处理 D2）、continuation 线性唯一（D3/E4 规格锚）、resume 脱糖为调用（D4）、E0007-E0009 诊断、GC 六来源（M5——活跃 continuation 帧根集） | 效应族增长（Stage 3 net）**不改变** L0/L1 语义（判据 J2）；效应与授权正交（D10 已验证——判据 J4） |
| **L3 授权** | 「交互被谁允许」——fail-closed 许可面 | 不定义被许可操作的**语义**（授权后行为 = L0/L1/L2 原样）；不做命名可见性（那是命名空间机制——[22 §3](./22-namespace-design.md)，两门对齐但分工） | `require` 声明语义（幂等集合/非符号 E2 错误）、门控注册表（`register_globals` 按授权面——未声明不注册）、E0006 编译期拒绝（R9 全路径）、FFI 线性令牌（消费全局生效）、E0010-E0012 | 只做进入过滤：授权变更不改语义只改可运行性（判据 J3）；授权族与命名空间族**边界对齐为设计不变量**（[22 §5](./22-namespace-design.md)） |

### 2.3 正交判据（可审计的四条 J 规则）

> 正交性的操作化定义（知识搜索 q4 实证——Ante《Why Algebraic Effects?》：「效应彼此组合良好」+ Contextual Modal Types 的类型化效应设计）：**两层正交 ⟺ 任一层的语义变更不引发另一层的语义变更**。四判据各配既有实测锚——**正交不是口号，是已验证的测试属性**：

| # | 判据 | 陈述 | 既有验证锚（758 测试中的实例） |
|---|---|---|---|
| **J1** | 值-控交换律 | L0 增删值类型（如 Stage 3 `char` 字面量）零 L1 归约规则变更 | r24 TD-010 引入 `HeapObj::Foreign` 装箱值——控制层归约零改动（`ffi_vm_tests` + bootstrap parity 全绿） |
| **J2** | 效应-语义独立性 | L2 增删效应族零 L0 值域/L1 归约变更 | r25 引入 Perform/Handle（原语集 9→11）——既有 706 测试零断言修改（M2 交付记录：「冻结路径零删改」） |
| **J3** | 许可-语义独立性 | L3 授权变更（收紧/放宽）零语义变更——只改「可运行程序集合」 | r8 门控引入：未声明程序从可运行变 E0006，已声明程序行为逐字节不变（`capability_tests` E0006 正负组） |
| **J4** | 效应-授权对偶分离 | 效应族与授权族独立演化：有授权无效应（`read-int` 门控纯解析）、有效应无授权（Perform State）均合法 | D10 能力-效应正交裁定（r25 effect-language-design）+ `print`（write 授权 + 输出效应）双轴独立变化实测 |

**J 规则的使用方式**（Stage 3 重构判定入口）：任何原语级/库级变更提案必须先过 J1-J4——违规 = 设计缺陷非实现细节。已知历史违规的治理先例：`set!` 横跨 L1/L2（控制形式携带副作用语义）——D5 裁定「`set! → Perform(State)` 维持语义等价证明而非实现义务」正是**把非正交点登记为受控债务**的处置（§5.6 卡片复引）。

### 2.5 三轴坐标系：「L3′」符号退役与 L×N×P 正交总图（v1.1 新增）

> v1.0 在 §4.3 与 §5.2 Module 卡使用了「L3′（命名机制）」记号——**本记号即日退役**：命名机制不是 L3 的旁支子层，而是与语义栈**正交的独立轴**。单轴坐标系的代价在 v1.0 已经显现：①「L3′」需要一个撇号来命名一个不在层级表里的层（未定义引用——审计轴 A5/A9 的实锤）；②`=` 的语义归属（关系域）与名形归属（运算符族）在单轴下无法同时表达。三轴坐标系一次解决两个问题：

```
语义轴 L0-L3（本文 §2——「程序由什么构成」）
  × 命名轴 N0-N4（22 §2——「名字如何存在与解析」）
  × 相位轴 P0/P1（02/03——「何时执行」）
  → 实现轴（crate 分层——15；工程轴非语义轴，§2.4 第 1 行）
```

**三轴判层规则**（v1.0 判层规则的推广）：任何语言特性问三个问题——①改变数据形态？（→语义轴 L0）②改变名字的组织或解析？（→命名轴 N 层）③改变执行时机相位？（→相位轴 P）。三轴可独立登记（`=` 双轴归属即合法状态）。**禁止**：用命名轴的层号伪装语义层（「L3′」反例）、用语义轴的层号伪装组织职责（Module 原语的 L1 组织面与 N2 机制面分立登记——§5.2 卡）。

**L×N 交互矩阵**（层级处理的单源对账表——每个交格标注 owner 与规则锚；空格 = 无交互（正交性的可审计形态））：

| | N0 符号宇宙 | N1 全局注册 | N2 模块层 | N3 局部绑定 | N4 保留字 |
|---|---|---|---|---|---|
| **L0 值域** | Symbol 值的存在性（intern 幂等——[22 R-N8](./22-namespace-design.md) 豁免） | 运算符族名形（R6 冻结 + R-N7 永驻） | —（值无名字组织） | — | — |
| **L1 控制** | VarRef 查找入口（名字→绑定） | 旧名兼容注册（过渡期 20 §7） | import 注入面（R-N1 第 2 步） | 词法绑定（ScopeSet 卫生——E3） | 关键字 = 语法标记（Reader 先行消费） |
| **L2 效应** | —（效应值不持名字） | 门控名按 require 面注入（R-N1 第 3 步） | `kerf/io` 模块面（对齐不变量 A——§4.3） | — | — |
| **L3 授权** | — | 门控注册表（fail-closed 红线 3） | import ≠ 授权（红线 1 + §4.4 组合闭包） | — | require/import 关键字面（声明入口） |

**相位轴交互**（两行）：Phase 1 宏体命名宇宙独立（[22 §4.2](./22-namespace-design.md)）；Phase 1 授权面 = 零（§4.5 本轮裁定——授权与相位正交的首次显式声明）。**矩阵的审计用法**：任何新特性提案先在矩阵定位交格——无交格可落 = 跨层违规（需受控债务通道登记）；双交格命中 = 双轴归属，须声明主从（§3.1 `=` 先例）。

**收益实例（`=` 的双轴归属）**：`=` 的**语义**属关系域（链式值相等——§3.1），**名形**属运算符族（R6 符号冻结）。v1.0 的单轴坐标系无法表达这种「一物双面」；三轴下这是合法状态：语义归属与名形归属是两个轴上的独立登记。同理 `error`：语义属诊断终止域（§3.1 新卡），名形属 R1 全词规则（`assert-eq?` 的 `?` 在 v0.5 别名层收敛）。

## 3. 库能力域架构（57 内置的能力域划分）

> v0.4 的 57 内置按**类别**分组（算术/比较/序对/…——09 §2 清单）；本节把它们升格为**能力域**（每个域是一等架构单元：有四要素、有正交边界、是 [20 §5.2](./20-surface-conventions.md) 模块树的架构解释）。域 ≠ 类别：类别是清单分组（描述性），域持职责契约（规范性——域边界违规 = 设计缺陷）。

### 3.1 十一域四要素表（v1.1 补全三域——覆盖闭合）

> **覆盖闭合声明（v1.1）**：八域（v1.0）→ 十一域（v1.1）——补算术运算符域、诊断终止域、横切泛函域三卡后，**57 注册内置 + prelude 自有五件，每名有家**（对账基表三源交叉：[09 §2](./09-stdlib.md) 清单 × [20 §8](./20-surface-conventions.md) 映射 × 本表——v1.0 的覆盖声明只到「八域为 20 §5.2 模块树提供架构解释」，未宣告逐名闭合，本轮补齐）。

| 域（→ v0.6 模块家） | 定位 | 边界 | 职责不变量 | 域正交（与其他域的零重叠声明） |
|---|---|---|---|---|
| **值谓词域**（→ `kerf/core`） | 值域判别：测试值属于哪个 L0 域 | 不变换值（`symbol->string` 属转换域）；不做结构操作 | 谓词全集完备覆盖 L0 值变体（r24 +5 补齐后：nil/bool/int/float/number/string/symbol/pair/list/procedure 十项完备） | 谓词只读不写——与全部域零副作用重叠 |
| **关系域**（→ `kerf/core`） | 恒等与相等（`eq`/`=`/`not`） | 不做排序（`<` 族名形属运算符域——R6 冻结；**语义**经 §2.5 双轴归属仍在本域）；不做查找（`member` 的 `eq?` 是**消费**关系原语非重复实现） | `eq` 恒等（即时按值堆按引用）/`=` 值相等（链式）/B5 语义分界不可合并 | 查找域消费本域（依赖方向单向） |
| **序对域**（→ `kerf/pair`） | 序对构造与访问（`cons`/`head`/`tail`——旧名 `car`/`cdr`） | 不做表级操作（表 = 序对链的**约定**，表操作属表域）；不做谓词（`pair?` 属谓词域） | nil 终结契约 + improper 拒绝（L0 值域不变量的执行者） | 表域建立在序对域之上（层次依赖非功能重叠） |
| **表域**（→ `kerf/list`） | 序对链的表语义操作（`length`/`nth`/`drop`/`member`/`assoc`…） | 不做变换字符串；遍历不越 nil 终结契约 | nil 契约继承 + B2 契约（v0.6 miss→nil 单一化）；查找按 `eq` 消费关系域 | 高阶函数不在本域（横切泛函域——§3.1 末卡） |
| **字符串域**（→ `kerf/string`） | 字符串值的全类操作 | 不做 I/O（输出属 io 域）；不做符号转换（转换域对偶 `string`↔`symbol` 双家） | 字符索引 Unicode 安全（字符级非字节）+ 码点序全族（TD-011）+ B1 契约（v0.6 index-of miss→nil） | 与 io 域正交：`string` 域零副作用（纯变换）——这是「为什么 `str-*` 不在门控表内」的架构答案 |
| **转换域**（`string`↔`symbol` 对偶双家） | 值域间有损/无损映射 | 不做数值解析（`read-int` 是 io 域——解析从**外部**读入是 IO 语义）；不做列表构造 | R4 双向双家（源侧 `to-X`/目标侧 `from-Y`——[20 §3](./20-surface-conventions.md)） | 解析属 io 域是**语义裁定非分类偏好**：`read-int` 失败报 IO 错误族（通道层语义） |
| **I/O 域**（→ `kerf/io`，门控） | 与外部世界的受权交互 | 不做字符串变换（`print` 只序列化不变换）；不做效应语义（print 的效应性由 L2 承载——域只持操作） | 元数纪律（B3 read-line 严格 0 参）+ EOF→nil 先例 + **全部成员在门控表**（域级授权对齐——§4.3） | 本域是 L0-L3 四层的交汇点（值序列化 × 控制调用 × 输出效应 × read/write 授权）——交汇 ≠ 职责混淆：每轴语义仍各归其层 |
| **字符判定域**（→ `kerf/char`） | Unicode 属性判定 | 不做字符变换（大小写在字符串域——大小写是字符串上下文语义） | White_Space/Alphabetic 属性 = Unicode 标准直引（非自创判定） | 引导私有 4 件（`pos-chars` 等）**不入用户面**（20 §5.2 既有裁定）——Reader 运行时服务域与本域边界 |
| **算术运算符域**（**N1 永驻**——[22 §3.7 R-N7](./22-namespace-design.md)） | 数学表面的零依赖骨架：四则 + `mod`（`+`/`-`/`*`/`/`/`mod`）与比较名形（`<`/`>`/`<=`/`>=`——**语义属关系域**，名形经 §2.5 双轴归属在本域） | 不做数值判别（`is-int` 属值谓词域）；不做字符串解析（`read-int` 属 I/O 域——解析从外部读入）；不做值相等语义（`=` 的链式值相等属关系域） | 数值塔运算纪律（Int×Int→Int 溢出检查/Float 提升/`mod` 拒浮点——L0 数值塔不变量的运算面执行者）+ B4 恒等元保留裁定（`(+)`→0/`(*)`→1） | **零依赖孤立点**：不依赖任何库域（零依赖最小骨架——OCaml core library 同型 [22 §2](./22-namespace-design.md)）；不迁移 `kerf/<模块>`（R-N7 永驻裁定——任何程序零 import 税） |
| **诊断终止域**（→ `kerf/core`） | 用户级终止性诊断的发起（`error`/`assert-eq?`） | 非效应（**不可拦截**——Perform 是可拦截通道，诊断吸收是终态 E5——[06 §3 错误吸收语义](./06-operational-semantics.md)：终止 ≠ 可拦截，两通道分立是设计裁定）；非编译期码位族（E00xx 结构化诊断 = 编译器面——[18 §6](./18-terminology.md)）；不做结构化错误值 | 消息部件规则（str 原文/其余 type_name 渲染——builtins.rs 实测口径）+ `assert-eq?` 恰 2 参 + 断言失败携带双值渲染 | L1 abort 语义（Err 吸收态）+ L0 消费值渲染；与 I/O 域零重叠（**终止不是副作用**——无外部世界交互，不入门控表） |
| **横切泛函域**（→ `kerf-prelude` 自有五件） | 任意可迭代域的高阶变换服务（`map`/`filter`/`foldl`/`foldr`/`for-each`） | 不持数据结构职责（服务一切可迭代域——表域是**首个消费者非唯一**）；不做谓词/关系；`for-each` 回调的副作用是**消费侧**效应非本域的（域自身零副作用） | 遍历协议 + 五件元数契约（prelude 实测）+ 回调调用的 E0004 元数而错误传递 | 建立在表域遍历协议之上（单向依赖）+ 消费谓词域/关系域回调；再导出能力归 N2 通用机制（[22 §3.6 R-N6](./22-namespace-design.md)——prelude 无特权） |

### 3.2 域正交的审计规则（域间依赖单向图）

```
横切泛函域（服务层——消费表域遍历协议 + 谓词/关系回调）
        ▲（服务方向）
值谓词域 ←─┐
关系域 ────┤（被消费）
           ├→ 表域 → 序对域 →（建立在 L0 值域上）
字符串域 ──┤                    转换域（string↔symbol 对偶）
字符判定域 ┘                    I/O 域（唯一的授权交汇点）

算术运算符域（N1 永驻孤立点——零依赖骨架，不进依赖图）
诊断终止域（终端点——消费 L0 渲染，Err 吸收终止，零出边）
```

**规则 D1（单向依赖）**：域依赖只允许图中方向——表域可用 `eq`（关系域），关系域不得用表域。**规则 D2（零双向）**：任意两域不得互相引用（string 域与 symbol 域经转换域对偶，但两域自身互不引用——转换语义集中在 R4 双家）。**规则 D3（副作用汇聚）**：副作用只允许出现在 I/O 域（其余域纯函数）——这是「`str-*` 族零门控」与「`io/*` 族全门控」的架构根据（门控表不是逐个函数的临时决定，是域级不变量的投影）。

## 4. 授权架构：三态模型与对齐不变量

### 4.1 授权三态（安全粒度的三个等级）

| 态 | 粒度 | 机制 | 既有实例 | 知识搜索实证（q2/q7） |
|---|---|---|---|---|
| **纯度态** | 函数级 | 无副作用即无授权需求——fail-closed 的默认面 | 51 个非 I/O 内置（§3.1 D3 规则） | ocaps：纯函数天然无能力需求 |
| **声明态** | 程序级 | `(require io read\|write)` 程序头声明→`register_globals` 按面注册→未声明引用 E0006 | 6 个 I/O 内置（r8 门控） | Pony/Austral：模块级能力声明面 |
| **令牌态** | 值级 | FFI `External` 线性令牌——持有才能消费，消费全局生效，NULL 哨兵 no-op | r30 `ALLOC/FREE_EXTERNAL` + E0010-E0012 | ocap 核心形态：能力=可传递的持有对象 |

**三态的设计逻辑**（递进收紧）：纯度态靠**静态纪律**（域 D3 规则）保证；声明态靠**程序头审查**（一次声明整面开放——粗粒度）；令牌态靠**逐值持有**（能力可传递可撤销——细粒度）。Stage 3 net/process 入场判定：socket/进程句柄属**令牌态**（可传递的 OS 资源持有）而非声明态——`kerf/net` 模块可见性（声明态）与 socket 值持有（令牌态）分层授权。

### 4.2 授权传播的禁止规则（fail-closed 的三条红线）

- **红线 1（import 不传播授权）**：`import kerf-io` 授予**名字可见性**，不授予 io 操作许可——`require` 是程序级声明，模块自身不携带能力。违例测试锚：`capability_tests` 中「import 后未 require 调 print → E0006」（v0.6 批次 M 增补 case——[22 §6](./22-namespace-design.md) 姊妹锚）。
- **红线 2（授权不改变语义）**：J3 判据的授权面表述——已授权程序行为逐字节不变（r8 引入门控时的实测口径延续）。
- **红线 3（缺省拒绝）**：未声明的门控名**不注册**（不是注册了调用时报错——编译期即不可见，E0006 指向声明缺失）；FFI extern 符号表空表默认 E0012（r30 run_program_with_externs fail-closed）。

### 4.3 对齐不变量（20 §5.3 的精确化修正）

> **对 20 §5.3 的架构修正**（r32 表述「『你要求了 io 能力』与『你引用了 io 命名空间』成为同一语义的两种表述」——**对齐不变量成立，但「同一语义」表述过强**）：

**修正后的不变量 A**：**授权族边界 ≡ 命名空间族边界**（`require io` 的门控内置全集恰好 = `kerf/io` 的模块导出全集——边界重合是设计要求）。**机制分工**（两门并存）：命名空间门管**名字可见性**（命名轴 N2 机制——[22 §2](./22-namespace-design.md)；v1.1 记号修正：原「L3′」已退役，见 §2.5），授权门管**操作许可**（L3 授权机制）。两者在 io 族重合是**最小完备设计的巧合必然**（I/O 域是唯一副作用域——§3.1 D3 规则下，副作用域 ⟺ 需授权域 ⟺ 命名空间独立成家）；**在 Stage 3 将出现分叉实例**（net 模块可见性 ≠ socket 令牌持有——§4.1 预判）。**同步纪律**：两门共享同一张授权表数据源（`require` 解析结果单源驱动 `register_globals` 面与模块可见性注入面——v0.6 批次 M 实施约束，防两门漂移）。

### 4.4 授权组合规则（require 的模块间组合语义——v1.1 新增）

> v1.0 的红线 1 只裁定了「import 不传播授权」的单边；组合面的另一边此前无 owner：**模块 A 的体需要 io write，程序 P 导入 A——P 需要声明什么？**（审计轴 A2/A7：授权的组合语义缺位——权限模型不能只回答单个程序的授权，还要回答授权如何跨模块组合。）

**裁定（传递闭包显式化）**：程序头 `require` = **该程序运行所需授权的传递闭包的显式声明**——导入链上全部模块的授权需求并集，必须由**入口程序**声明。模块体自身的 `require` 声明 = 模块的**授权需求元数据**（interface 声明——供编译期核对与诊断），不是授权获得（获得只有入口声明一条路）。

| 判据 | 内容 | 依据 |
|---|---|---|
| 组合语义 | 授权责任上移入口：`授权面(程序) ⊇ ⋃ 授权需求(导入闭包)` | WASI「无环境权威」模型（q1 实证：能力由嵌入者显式授予，组件只能声明需求——kerf 的入口程序 = 嵌入者、模块 = 组件同构）；ocap 组合 = 显式布线（q4：wiring capabilities together）非环境继承 |
| 静态核对 | 模块需求 ⊆ 程序声明，**编译期可判定**（module registry 增授权需求字段——批次 M 实施件） | 红线 3 fail-closed 的组合面延伸（违规 = 编译期拒绝，非运行时惊喜） |
| 诊断增强 | E0006 携带缺失需求提示（「模块 kerf-io 需要 (require io write)」） | 诊断三段式（02 §5）——闭包规则使缺失原因可定位到模块 |
| 不变性 | 红线 1 维持：import 授予名字可见性，模块需求声明授予的仍是零授权 | §4.2 三红线不动——组合规则是红线 1 的**推论非修正**（import 不传播授权 ⟺ 授权责任上移入口，同一定理的正反两面） |

**Stage 3 net 组合预判**：net 族 = 声明态 + 令牌态双层（§4.1）——传递闭包规则只约束**声明态**；令牌态（socket 值持有）不经 require 组合，按值传递自身携带（ocap 原教义：能力 = 持有物——[22 §5.3](./22-namespace-design.md) 零 N2 投影行同锚）。

### 4.5 编译期权威边界（Phase 1 零授权面——v1.1 新增）

**裁定**：Phase 1（宏展开期）= **纯符号变换，零授权面**。当前 syntax-rules 变换器天然合规（模式替换无 I/O 通道）；本裁定把「天然合规」升格为**设计纪律**——授权与相位正交的首次显式声明（L×N×P 三轴中相位轴的授权面）。任何引入编译期任意代码执行的提案（syntax-parse 类宏 DSL——[03 推迟项](./03-macro-system.md)）必须先过**编译期权威三判据**：

1. **确定性**：同输入同输出（可复现构建——编译产物不依赖环境状态）
2. **零外部 I/O**，或经**编译期令牌**（接口位预留：显式授予的编译期能力形态，与运行时令牌态同型不同宇宙；Stage 3+ syntax-parse 评估窗口裁定形态）
3. **展开可终止**（预算制——与 VM instruction budget 同型纪律）

**依据（q2 实证——Rust 生态的反面教材与 2026 收敛方向）**：proc-macro 任意代码执行 = 编译期安全缺口（「innocent-looking 宏的巨大攻击面」+ build.rs 侧信道）+ 不可复现构建 + 编译时间恶化；社区收敛方向 = 沙箱化/确定性/可复现（Pre-RFC: Sandboxed deterministic reproducible Wasm macros——2026 前沿正朝此收敛）。**kerf 从设计起点即站对侧**：原则 3（元层分离）+ 原则 5（相位分离）的授权面延伸。相位轴的授权面全景：P0 = 三态授权（§4.1）；P1 = 零授权（本裁定）；P1→P0 的唯一通道 = 宏**产生**代码（不能执行 Phase 0 代码——[03 §1 规则 1](./03-macro-system.md) 的授权面同义表述）。

## 5. 原语级四要素卡与结构重构分类学（原语迁移 ≠ 重命名）

> 用户指令的直接回应：「对原语级别的内容不是简单的重命名（之前存在相关讨论并已经在计划中推进重构设计）」。既有讨论 = [01 §7.3](./01-core-forms.md) E1-E5 裁定 + [01 §8.3](./01-core-forms.md) 迁移映射 + [primitive-migration-evaluation.md](../develop/v0/stage-2/primitive-migration-evaluation.md)（r18 五项评估）。本节把它们收编为**结构重构分类学**：11 个现行原语每个一张四要素卡，Stage 3 目标形态的迁移性质逐项分类——**重命名只是六类迁移性质中最浅的一类**。

### 5.1 结构重构分类学（六类迁移性质）

| 迁移类 | 定义 | 实例（01 §8.3 映射表） | 正交收益 |
|---|---|---|---|
| **M-R 重命名**（Rename） | 同构改名——语义结构零变更 | `App→Apply`、`If→Branch` | 零（纯可读性） |
| **M-D 脱糖**（Desugar） | 消除语义重叠原语——归约为其他原语的组合 | `Define→Apply[Fn,value]`、`Begin→Let 链` | **消除非正交点**（§5.5 收益论证） |
| **M-I 索引化**（Index-encode） | 名字解析编译期固化——消除运行时查名 | `VarRef→Var(de Bruijn)`、`Lambda→Fn(params: usize)` | 求值器零环境链（Kernel/Racket kernel 对照——q3 实证） |
| **M-L 层级迁移**（Layer-move） | 原语降层/升层——职责归还正确的层 | `Module→模块系统层`（L1 原语→相位机制）、`quote+#%datum→Const`（多层转义→L0 单层） | L1 瘦身——控制层不再携带组织与转义职责 |
| **M-E 效应化**（Effectify） | 副作用语义升层 L2——从控制形式变效应操作 | `SetBang→Perform(State)`（D5：**语义等价证明在位，实现义务维持不迁移**——set! 保留原语） | L1/L2 非正交点的最终消除路径（受控债务的清偿计划） |
| **M-A 增原语**（Add） | 新增独立职责原语 | `Let`（ANF 锚点）、`Perform/Handle`（r25 已落地） | 每个新原语必须持**不可归约职责**（否则 M-D 逆命题触发——§5.5 判据） |

### 5.2 现行 11 原语四要素卡（冻结形态——Stage 2 事实基线）

| 原语 | 定位 | 边界 | 职责 | 正交依赖（消费哪些层） |
|---|---|---|---|---|
| `Lambda` | 计算的抽象单元 | 不捕获环境语义（闭包=运行时组合物非原语职责） | 参数绑定 + 体组合；TCO 目标位 | L0（参数值域）；发射 L2 效应（体） |
| `App` | 计算的执行单元 | 不做参数求值序裁定（序=`Begin`/`Let` 域） | β-归约触发点 + 元数核对入口 | L1 全部；错误面 E00xx |
| `If` | 计算的分支单元 | 不做多值/模式匹配（match=Stage 3 蓝图——非本原语扩张） | Bool 判定二路分派 | L0 Bool 域 |
| `VarRef` | 计算的引用单元 | 不做作用域决策（解析=ScopeSet 机制） | 名字→绑定的查找点 | 展开层命名制（E3 永久保持） |
| `Literal` | 计算的常量单元 | 不做类型裁定（数值塔判定=L0 职责） | 字面量→值域单射（r21 INC4 标记化） | L0 全值域 |
| `SetBang` | 可变绑定的赋值单元（**受控非正交点**） | —（非正交：控制形式携带 L2 语义） | 就地重绑 + GC 写屏障配合 | L1+L2 双层（D5 登记债务） |
| `Begin` | 顺序组合单元 | 不做绑定（`Let` 专职） | 求值序 + 尾位语义 | L1 |
| `Define` | 顶层锚定绑定（**可脱糖**） | 不做表达式位置绑定（`Let`） | 名字→值的全局锚定 | L1（=Lambda+App+SetBang 组合语义——[01 §7.1 数量真相](./01-core-forms.md)） |
| `Module` | 相位分离单元（**层级迁移候选**） | 不做命名解析（§22 命名层专职） | 编译单元 + import/export 组织 | L1 组织面；N2 命名面（22——v1.1 记号修正：双轴分立登记，§2.5） |
| `Perform` | 效应执行原语（r25） | 不做效应语义定义（handler 体定义） | 效应值发起 + continuation 捕获 | L2 核心；L0（效应值域） |
| `Handle` | 效应处理原语（r25） | 不做授权（许可=L3） | handler 子句匹配 + resume 装订（线性唯一 D3） | L2 核心；L1（handler 体） |
| `Require`（声明变体） | 程序级授权声明（非语义原语） | 不做语义（J3——授权零语义载荷） | L3 唯一语言入口；幂等集合语义 | L3 |

| `Apply` | M-R | — | E5 同窗 |
| `Branch` | M-R | — | 同上 |
| `Var`（index） | M-R + M-I | 展开层命名制**不迁**（E3 永久保持——Var 索引化仅 IR 层） | E3 分层裁定 |

### 5.4 Require 的地位澄清（一个易混点）

`Require` 是**声明变体**（[01 §6](./01-core-forms.md)），不是语义原语——它出现在冻结契约「11 语义原语 + Require 声明变体」的措辞里，但架构上属 L3（J3：零语义载荷）。**「声明面与语义面两层不合流」**（01 §6 既有裁定）在本文坐标系的表述：L3 授权语言永不升入 L1-L2 语义层——授权演化（net 增族）不触碰归约规则。

### 5.5 非正交点消除的正交收益论证（为什么 M-D/M-E 值得做）

**Define 的非正交代价**（§7.1 数量真相的技术含义）：`Define ≡ Lambda+App+SetBang 组合`——编译器必须维护**两条等价路径**（顶层 define 展开 vs 手写组合），自举 parity 链（门 A 字节码全等测试）为此多付一组等价性断言。**脱糖后**：单一路径，parity 面收缩。**Begin/`Let` 重叠**同理（`begin a b ≡ ((lambda (x) b) a)`——01 §7.3 已注记）。**SetBang 的 L1/L2 跨层**：受控债务（D5）——收益已论证（效应统一拦截面），时机成本已裁定（Stage 3 一次性窗口），本文仅持卡片登记。**正交度提升的量化口径**（Stage 3 验收建议）：非正交点计数 3（SetBang/Define/Begin）→ 1（SetBang 维持）或 0（若 M-E 兑现）。

### 5.6 卡片纪律（新原语准入）

Stage 3+ 任何新原语提案必须附四要素卡 + 通过两条准入判据：**①不可归约性**（不能由既有原语组合等价表达——否则 M-D 逆命题：应该脱糖不是新增）；**②单层归属**（J 判据过——跨层原语需按 D5 形态登记受控债务）。
