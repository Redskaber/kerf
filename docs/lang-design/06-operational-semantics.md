## 1. 语义域的形式定义

### 1.1 语法域（归约的对象）

归约规则的左端对象是展开产物 `CoreExpr`（[01-核心原语 §2](./01-core-forms.md) 的九个正交原语）。九原语与 `literal_value` 的定义在 Stage 0 已冻结（`kerf-core/src/expr.rs`，与 stage0.md §3.2 的 OCaml 定义逐字段一致）：`Lambda / App / If / VarRef / Literal / SetBang / Define / Begin / Module`。**`quote` 不独立成原语**——Reader 将 `'x` 简写读取为 `(quote x)`，Expander 将其归约为 `Literal`（点对结构在 `literal_value` 中承载），故 quote 的语义即 R4（字面量恒等归约）。

### 1.2 运行时域

```text
v   ::= #n | #f | nil | ⟨s⟩ | ⟨z⟩ | (v . v) | ⟨λ(x₁…xₙ).e, ρ, C⟩ | b      值
ρ   ::= ∅ | ρ[x ↦ v]                                                        环境（词法链）
C   ::= 共享捕获单元格组（Rc<RefCell<Value>> 槽的有限序列）                   闭包捕获描述
σ   ::= (H, R)                                                              堆（对象集 H 与根集 R）
b   ::= 内置函数句柄（driver 注册，见 [09-标准库 §2](./09-stdlib.md)）
```

- **值 `v`**：布尔、整数、浮点、字符串、nil、点对（堆分配）、闭包（`⟨λ(x₁…xₙ).e, ρ, C⟩`：代码 + 定义环境 + 捕获单元格组）、内置函数。与 `kerf-vm/src/value.rs` 的 `Value` 一一对应。
- **环境 `ρ`**：有限映射，实现为词法父子链（`Env::child / lookup / define / set`）。`lookup` 沿链向父级搜索；`define` 在**当前**层新增绑定；`set` 修改链上**已有的**绑定（未绑定则失败）。
- **堆 `σ`**：点对等对象在堆上分配；根集 `R`（VM 栈、帧局部、全局环境、外部登记引用，见 [05-运行时 §4](./05-runtime.md)）决定可达性。

### 1.3 求值状态与判断

小步归约作用在**求值状态**三元组 `⟨e, ρ, σ⟩`（表达式 / 环境 / 堆）上：

```text
⟨e, ρ, σ⟩ → ⟨e', ρ', σ'⟩          一步归约（状态内焦点归约）
⟨e, ρ, σ⟩ → Err(ε)                错误吸收（终止，见 §3）
⟨e, ρ, σ⟩ ⇓ v                     多步归约到值（→ 的自反传递闭包）
```

**求值顺序契约（编译与求值器共享）**：`App` 的被调函数与实参**从左到右**求值（`kerf-vm/src/eval.rs` 与 `kerf-compiler` 的生成顺序一致，[04-字节码 VM §3](./04-bytecode-vm.md)）；`Begin` / `Module` 体按源序求值。该顺序是定理 T1 的归纳基础之一——两条执行路径若顺序不同则互查不可判定。

## 2. 九原语的小步归约规则

> 记号：`ρ[x ↦ v]` 表示环境扩展/更新；`σ ⊕ o` 表示堆分配对象 `o`；规则按原语编号 R1–R9；辅助规则 βv / δ / E0–E8。每条规则标注实现锚点（冻结源码位置），保证规范与代码互相锚定（[17-设计原则 §1 原则 8](./17-principles.md)：语义形式化是正确性的**可验证**规范）。

### R1 Lambda（闭包构造——捕获定义环境）

```text
(L1)  ⟨(lambda (x₁…xₙ) e), ρ, σ⟩ → ⟨⟨λ(x₁…xₙ).e, ρ, ε⟩, ρ, σ⟩
```

闭包在**构造时**快照定义环境 `ρ`（词法作用域）。闭包捕获的**可变**绑定（`SetBang` 作用域链上的变量）经共享单元格 `C` 实现读写共享——两条执行路径的捕获协议等价性是定理 T1 的关键引理（L3，§5.2）。

### R2 App（应用——call-by-value，从左到右）

```text
(A1)  ⟨e_f, ρ, σ⟩ → ⟨e_f', ρ, σ'⟩
      ⟹ ⟨(e_f e₁ … eₙ), ρ, σ⟩ → ⟨(e_f' e₁ … eₙ), ρ, σ'⟩          函数先求值

(A2)  ⟨eᵢ, ρ, σ⟩ → ⟨eᵢ', ρ, σ'⟩   (e_f 已是值, e₁…e_{i-1} 已是值)
      ⟹ ⟨(e_f v₁ … v_{i-1} eᵢ … eₙ), ρ, σ⟩ → ⟨(e_f v₁ … v_{i-1} eᵢ' … eₙ), ρ, σ'⟩

(A3)  βv 规约（闭包应用）：
      ⟨(⟨λ(x₁…xₙ).e, ρ_c, C⟩ v₁ … vₙ), ρ, σ⟩
      → ⟨e, ρ_c[x₁ ↦ v₁, …, xₙ ↦ vₙ], σ⟩                          参数数量 ≠ n 时走 E2

(A4)  δ 规约（内置函数应用）：
      ⟨(b v₁ … vₙ), ρ, σ⟩ → ⟨δ(b, v₁…vₙ), ρ, σ'⟩                  δ 语义见 [09-标准库 §2](./09-stdlib.md)；
                                                                    σ' 含 δ 的堆效应（如 cons）
```

实参绑定方式为**新帧子环境**（`ρ_c` 的 child），非原地覆盖——递归闭包与外部引用互不干扰。`arity` 不匹配（E2）是**硬错误**而非默认值填充（§2.1.1 原则：报错 > 静默）。

### R3 If（分支——truthy 显式化）

```text
(I1)  ⟨(if #t e_t e_e), ρ, σ⟩ → ⟨e_t, ρ, σ⟩
(I2)  ⟨(if #f e_t e_e), ρ, σ⟩ → ⟨e_e, ρ, σ⟩
(I3)  ⟨(if v e_t e_e), ρ, σ⟩ → Err(TypeMismatch)   当 v ∉ {#t, #f}
(I4)  ⟨(if e_c e_t e_e), ρ, σ⟩ → ⟨(if e_c' e_t e_e), ρ, σ'⟩   当 ⟨e_c, ρ, σ⟩ → ⟨e_c', ρ, σ'⟩
```

**truthy 语义显式定义**：条件必须是布尔值；整数、nil、点对一律不参与真值判定（对比 Scheme 的「除 #f 外皆为真」——kerf 的选择是「类型安全优先」原则 [17-设计原则 §1 原则 21](./17-principles.md) 的直接落地）。I3 在编译侧对应 `JumpIfFalse` 的类型检查陷阱（[04-字节码 VM §3](./04-bytecode-vm.md)）。

### R4 Literal（字面量恒等——含 quote 语义）

```text
(L4a) ⟨k, ρ, σ⟩ → ⟨k, ρ, σ⟩                 标量字面量已是值（Int/Float/Bool/Nil/Str）
(L4b) ⟨(v₁ . v₂)_{lit}, ρ, σ⟩ → ⟨(v₁ . v₂), ρ, σ ⊕ (v₁ . v₂)⟩   点对字面量在堆上构造
(L4c) quote 归约（展开期完成，非运行时规则）：
      (quote e) ⟼ Literal(e)                数据即代码——'x 读作 (quote x)，展开为字面量
```

点对字面量（quote 产物）的**构造期**在求值时（`eval_literal` 在堆上递归构造）；其**内容**在归约后不可变（不存在对字面量点对的变更原语——变更仅经 `SetBang` 作用于变量绑定）。

### R5 SetBang（赋值——仅已有绑定）

```text
(S1)  ⟨(set! x v), ρ, σ⟩ → ⟨v, ρ[x ↦ v], σ⟩          当 x ∈ dom(ρ)（沿词法链）
(S2)  ⟨(set! x e), ρ, σ⟩ → ⟨(set! x e'), ρ, σ'⟩      当 ⟨e, ρ, σ⟩ → ⟨e_e', ρ, σ'⟩（先求值右部）
      ⟨(set! x v), ρ, σ⟩ → Err(UnboundVariable)      当 x ∉ dom(ρ)
```

赋值沿**词法链**定位目标层（`Env::set`）；返回值为被赋的值。对闭包捕获变量的赋值经共享单元格对**所有**捕获方可见（L3 引理的形式对象）。

### R6 Define（定义——新增绑定）

```text
(D1)  ⟨(define x e), ρ, σ⟩ → ⟨e, ρ, σ⟩ 先求值右部；
      ⟨(define x v), ρ, σ⟩ → ⟨v, ρ[x ↦ v]_{顶层}, σ⟩   在当前环境层新增绑定
```

**两位置语义**（Expander 裁定，[03-宏系统 §4](./03-macro-system.md) 陷阱 3）：模块顶层 `define` 保留原语；函数体内部被展开器改写为 `SetBang` + 预绑定（`letrec` 推导），因此 R6 的归约仅发生在顶层序列。`define` 不可重定义已绑定符号（重复定义走 E6）。

### R7 Begin（序列——值为末项）

```text
(B1)  ⟨(begin), ρ, σ⟩ → ⟨nil, ρ, σ⟩
(B2)  ⟨(begin v e₂ … eₙ), ρ, σ⟩ → ⟨(begin e₂ … eₙ), ρ, σ⟩   值丢弃（副作用经 S1 已发生）
(B3)  ⟨(begin e₁ … eₙ), ρ, σ⟩ → ⟨(begin e₁' … eₙ), ρ, σ'⟩  当 e₁ 非值且可归约
```

### R8 VarRef（变量引用——词法链查找）

```text
(V1)  ⟨x, ρ, σ⟩ → ⟨ρ(x), ρ, σ⟩                   当 x ∈ dom(ρ)
(V2)  ⟨x, ρ, σ⟩ → Err(UnboundVariable)           当 x ∉ dom(ρ)
```

### R9 Module（模块——Stage 0 单模块裁定）

```text
(M1)  ⟨(module m (import …) (export …) e₁ … eₙ), ρ_g, σ⟩
      →* ⟨v, ρ_g', σ'⟩     其中 ρ_g' = 归约序列 e₁…eₙ 对 ρ_g 的累积效应；
                            import/export 在运行时无归约动作（编译期由 ModuleRegistry 处理，[03-宏系统 §1](./03-macro-system.md)）
```

**Stage 0 裁定**：模块体在全局环境 `ρ_g` 直接求值（单模块世界）；`declare / visit / instantiate` 三操作的完整相位语义与传递依赖先行次序属编译期簿记，不在小步归约中显现。多模块实例化隔离（每模块独立命名层）推迟至 Stage 1+（[12-路线图 §2.5](./12-roadmap.md) 演进矩阵）。

## 3. 错误吸收语义

错误是**吸收态**（不归约、不恢复、直接终止该求值）：

```text
(E0)  ⟨e, ρ, σ⟩ → Err(ε) ⟹ 无后续状态（吸收）
(E1)  TypeMismatch      —— If 条件非布尔（I3）
(E2)  ArityMismatch     —— βv 参数数 ≠ 形参数（A3 卫式条件失败）
(E3)  UnboundVariable   —— VarRef/SetBang 链上无绑定（V2/S1）
(E4)  NotCallable       —— App 被调者非闭包/非内置
(E5)  BuiltinError      —— δ 规约失败（类型/域错误，[09-标准库 §2](./09-stdlib.md)）
(E6)  DuplicateDefine   —— 顶层重定义
(E7)  RuntimeError      —— I/O 通道失败（[05-运行时 §1](./05-runtime.md)）
(E8)  内部不变式破坏    —— 仅可能来自编译器缺陷（如栈失衡），视为编译器 P0 缺陷而非用户错误
```

错误携带 `Span`（源位置）传播至诊断层（[02-语法模型 §3](./02-syntax-model.md)）——错误信息是一等公民（[17-设计原则 §1 原则 16](./17-principles.md)）。**无未定义行为**：任何输入要么归约到值、要么进入确定的 Err 态（E0–E7 全集覆盖用户程序可触发的全部终态；E8 是编译器自身的质量边界）。

## 4. GC 不可观测性引理

**引理 L-GC**：设 `⟨e, ρ, σ⟩ →* ⟨e', ρ', σ'⟩` 为任意归约序列，GC 周期 `collect: σ → σ₁`（标记-清除，[05-运行时 §4](./05-runtime.md)）若满足根集完备不变式，则：

```text
⟨e, ρ, σ⟩ →* v  ⟺  ⟨e, ρ, collect(σ)⟩ →* v     （归约结果与 GC 触发点无关）
```

证明要点：(1) 标记阶段从根集可达的对象集 = 归约序列当前状态引用的对象集（根集完备不变式）；(2) 清除仅回收不可达对象，而不可达对象不出现在任何后续归约规则的对象位置（归约规则只访问 ρ 与 σ 中根可达对象）；(3) 分配计数驱动的触发时机（[05-运行时 §2](./05-runtime.md)）因此不影响语义——这是「分配零内卷」与「安全点」两条实现不变式的理论依据。GC 冷却退避（性能机制）同理不改变语义。

## 5. 编译正确性定理

### 5.1 定理陈述（T1）

```text
T1（编译正确性）：
  对任意良构程序 p（展开产物 CoreExpr 序列）与初始环境 ρ₀、初始堆 σ₀：
    若  ⟨p, ρ₀, σ₀⟩ ⇓ v   （元循环求值器路径）
  则  VM_run(compile(p), ρ₀, σ₀) ⇓ v'  且 v ≡ v'（值结构等价，见 5.2 L4）
```

其中 `compile: CoreExpr → CodeBuf`（[04-字节码 VM §2](./04-bytecode-vm.md)，40 操作码，含 v5.1 新增的 `DefineGlobal`——D1/E6 语义的第 40 号冻结契约），`VM_run` 是迭代式帧栈执行（[04-字节码 VM §3](./04-bytecode-vm.md)）。

### 5.2 证明纲要（三引理归纳）

- **L1（指令组局部保持性）**：对每个操作码组（栈操作 / 变量访问 / 控制流 / 函数操作 / 算术比较，[04-字节码 VM §2](./04-bytecode-vm.md) 的五组分类），逐组证明：指令的栈效应 + 帧效应 = 对应 CoreExpr 子项一步归约的状态效应。归纳基础覆盖全部 40 操作码（编译器测试的「回填零占位断言」是 L1 的机械化检查点）。
- **L2（求值顺序一致性）**：编译产码顺序（App 左到右、Begin 源序）与 R2 的 A1/A2 顺序契约一致（§1.3）。
- **L3（捕获协议等价性）**：`CLOSURE` 指令的共享单元格捕获（`Rc<RefCell>` 槽）与 βv 的子环境扩展在**可变捕获**情形下行为等价——两条路径对 `SetBang` 作用域链变量的读写均经同一逻辑单元格（这是 Stage 0 关键修复「捕获值快照 → 共享单元格」的理论定案：快照语义会破坏 R5/S1 对闭包的可见性，即不满足 T1）。
- **L4（值结构等价 `≡`）**：标量按值相等；点对按递归结构相等；闭包按（参数表、代码体、环境可达图）同构相等——堆位置可以不同（两路径是两个堆），但**可观测行为**（打印、比较、继续求值）一致。

### 5.3 定理的运行时验证（双路径互查）

T1 的机器验证载体是 [11-测试基础设施 §2.4](./11-testing.md) 的**双执行路径互查**：每个测试程序同时经 `eval` 与 `VM_run` 执行并逐字节比对结果（Stage 0 集成测试 73 项全部内置互查断言）。互查通过是 T1 的**必要条件**验证（非充分证明——定理本身的证明靠 L1–L4 的归纳论证，互查是在每个具体程序上的实例化检查）。反例即 P0 缺陷：历史上 CLOSURE 原型切换与捕获协议修复均由互查暴露。

### 5.4 适用边界

T1 覆盖 Stage 0 的确定性单线程语义。以下超出当前定理范围（对应的扩展定理列入演进矩阵）：并发内存模型（Stage 3，[13-能力矩阵 §4](./13-capability-matrix.md) 决策 1）、Effect Handlers 语义（接口预留档，[13-能力矩阵 §3.1.1](./13-capability-matrix.md)）、编译缓存命中路径（等价性由 `CompilationCache` 契约的键完备性保证，[13-能力矩阵 §3.1.4](./13-capability-matrix.md)）。
