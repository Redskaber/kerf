## 1. 测试基础设施：三层测试（原 §13.2）

三层测试：快照测试（确定性输出）、黄金文件测试（预期输出 diff）、自举测试（两次编译自身，比较字节一致性）。

## 2. 四类测试类型详解（从原 §13.2 与 §21.3 Stage 0 验收标准提取）

### 2.1 快照测试（确定性输出）

对给定输入程序，捕获管线各阶段（Token 流 / 展开结果 / 字节码 / 执行输出）的确定性输出并与快照比对。适用于 Reader（Week 1 验证标准：≥20 个 Reader 快照测试）与整体管线（Week 4 / 里程碑验证：≥50 个快照测试全绿，见 [12-路线图 §1/§3.3](./12-roadmap.md)）。

### 2.2 黄金文件测试（预期输出 diff）

预期输出以黄金文件形式存储，diff 检测行为变更。与快照测试互补：快照面向确定性中间表示，黄金文件面向端到端程序输出（含 print/write_line 的 stdout）。

### 2.3 同结果测试（Rounds-testing）

两次编译的输出必须字节一致的验证（术语定义见 [18-术语表](./18-terminology.md)）：
- **自举形态**：编译器两次编译自身，比较输出字节一致性（原 §13.2 的自举测试；对应 [07-自举策略 §1](./07-bootstrap-strategy.md) 流水线 Stage 3 自验证，及 GCC 三阶段自举的阶段 2/阶段 3 字节一致要求——见 [00-总览 §4.5](./00-overview.md)）；
- **复现构建属性**：相同输入必然产出字节一致输出的构建属性（同结果性，Reproducibility）。

### 2.4 双执行路径互查（eval 与 VM 互查）

原 §21.3 Phase 1（语义验证）的目标：**用双执行路径（eval 与 VM 互查）验证 9 个核心原语的语义正确性**——元循环求值器（[13-能力矩阵 §2.4](./13-capability-matrix.md)）与字节码 VM（[04-字节码 VM](./04-bytecode-vm.md)）两条执行路径对同一程序必须产出相同结果。这直接对应 [06-操作语义 §5](./06-operational-semantics.md) 的编译正确性定理 T1（含三引理证明纲要与适用边界）：对任意源程序 `p`，如果 `p →* v`，那么 `compile(p) →* v`。互查通过是 T1 的必要条件验证（非充分证明——定理靠归纳论证，互查是逐程序实例化检查，反例即 P0 缺陷）。

## 4. 用例运行器 `kerf test`（r8 批次 D 新增——测试面即语言面）

**动机**：Stage 0 的测试全部由宿主（Rust cargo test）承载——kerf 程序自身没有原生断言/用例形态。r8 引入 `kerf test` 子命令（`test_source` API + CLI），以**零新语法**把测试面锚定在语言面上：断言 = `(= a b)` 谓词，用例 = 顶层表达式。这是自举进程的语义前身——Stage 1+ 用 kerf 子集重写测试运行器时，约定不变、实现替换（渐进替换原则 §28）。

**约定**（语义契约，tests/v0/stage1/plan/test_runner_tests.rs 18 case 锁定）：
1. **前置/用例切分**：顶层形式中 define/set!/module/require（状态与声明）= **公共前置**，其余顶层表达式 = **用例**（源序保持）；
2. **前置逐用例重放**：每用例独立重放前置（前置 ++ 用例编译为一个切片）——用例间状态隔离（v0 口径：**用例是前置的纯函数**，用例内 set! 不泄漏进后续用例）；
3. **PASS 判定**：求值无错且值非 `#f` → PASS；运行时错误或 `#f` → FAIL（false 为唯一失败值——nil/零等非 bool 值均通过）；
4. **短路 + 恢复**：case 内任意深度失败（效应逃逸）即停该 case；边界捕获后下一 case 续跑——失败不毒化后续；
5. **front 错误面**：源级 read/expand/R9（E0006）错误 → 整体 DriverError（非用例 FAIL）；
6. **执行路径** = 生产 VM 路径（§11 无平行语义；编译缓存内容寻址复用）。

**与效应系统的关系**（消费面）：短路/恢复的机械载体是 [13-能力矩阵 §3.1.1](./13-capability-matrix.md) r8 做实的类型化一次性逃逸层——`fail_test` 从用例体内任意深度 `perform_escape`，`handle_escape` 边界捕获后判 FAIL 并续跑。这是 Effect Handlers「编译器内部做实」的首个端到端消费面（D-任意节点标尺的机械证明）。

**形态学对照**：与 Racket rackunit（check-eq? 形谓词 + test-begin 组织）同构——谓词即断言、无新语法；与 cargo test 的 per-test 隔离语义对齐（进程内环境/堆重建替代进程隔离）。
