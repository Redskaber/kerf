## 0. 设计轮定位声明（§1.2「写文档」路由）

本文件回答用户指令 41-a 的三个子问题：**(1) 当前能力模型的定位与
职责边界是否过窄？**(2) 真实的能力模型应覆盖什么域（设计/契约接口/
职责/能力/边界）？**(3) 能力模型与其他同层预留（effect/multistage/
cache/FFI/toolchain）之间存在哪些可预期的化学反应？**

**一句话结论**：**是——当前实现把「能力安全模型」（capability
security model）与它的第一实例「IO 族」在命名、类型、职责三个层面
耦合了**；设计意图（12 §2.4.5 的 Stage 2「完整能力模型」口径）远比
实现宽，但模型层没有自己的冻结位。本设计裁定**模型层与族层分离**
（M1 迁移零破坏），并在 reserved/ 层为模型骨架冻结类型形状
（P3——本批次交付 `capability_model.rs`）。

## 2. 真实 vs 当前：七面对照（用户指令 ① 的系统化回答）

| 面 | 当前（r18 实况） | 真实（设计意图 + 通用能力模型域） | 差距判定 |
|---|------------------|----------------------------------|---------|
| **设计** | 「能力门控 I/O」——require io read/write + 令牌门控 stdio | 「能力安全模型」：权限的颁发/传递/削弱/撤销/验证的通用演算；I/O 是首个被门控的资源族 | **窄**——模型被实例遮蔽 |
| **契约接口** | `CapabilityIO` trait（read_line/write_line 两方法）+ 两令牌结构 + IOError | 模型层契约：族（family）抽象 + 令牌演算（mint/attenuate/delegate/revoke）+ 授权管线（grant）形状；族层契约：每族自己的操作 trait（IO 族=现状） | **缺模型层**——族契约完备、模型契约无位 |
| **职责** | capability.rs 承担「require 提取 + 铸造 + R9 验证 + stdio 实现 + 内置消费参数化」五职责（全部 IO 具体化） | 模型层职责：统一授权面（grant 管线）+ 统一验证引擎（数据驱动表）+ 令牌演算语义；族层职责：操作语义 + 资源边界 | **职责混杂**——管线通用性与数据 IO 特异性同居一文件一命名族 |
| **能力覆盖** | 2 个能力变体（IoRead/IoWrite）、7 个门控内置名 | 设计域至少 10 族候选（io/net/process/file/time/random/memory-external/ffi/eval-stage/compilation-service）+ 令牌演算 6 操作 | **子集关系成立**——IO ⊂ 能力模型，用户判断正确 |
| **边界** | 边界 = stdio 两流；`kerf_runtime::io` 全局函数降为 OS 边界层 | 边界 = 一切「副作用资源」：外设、网络、进程、外部内存、异构调用、代码执行本身 | **窄**——仅覆盖最小资源面 |
| **命名** | capability_io / IoGrant / IoRequirements / IOError / CapabilityIO / READ_GATED | 模型层名：CapabilityModel / Grant / TokenCalculus；族层名：io 族（保持）/ ffi 族（CPointer 已有）/ net 族… | **命名耦合**——模型概念被 IO 前缀占据（B2/B5 证据） |
| **扩展面** | required_capability 表 + 枚举注释 + F2 修复注记（任意流程节点增族） | 扩展须同时动：kerf-core 枚举 + 门控表 + Grant 结构 + require 语法族名 + reserved 族契约文件——**五点无统一模型锚** | **结构风险**——每族新增都是一次五点手术，无冻结位保证不改形状 |

**差距总结**：不是「实现错了」——B1-B4 证明族实例纪律完备；而是
「模型层缺席」——通用管线被 IO 命名具体化，且 reserved/ 层没有模型
骨架的冻结位（违反 13 §3.3 预留原则：「不需要在 Stage 0 实现，但必须
在数据结构中预留位置，否则后期引入需要破坏性重构」——net/process
族引入时 Grant/验证引擎/require 语法都会被触及）。

## 4. 模型全景（真实域的形式化）

### 4.1 族分类学（能力模型覆盖域——候选族 × 成熟度）

| 族 | 权限对象 | 现状 | 引入窗口 |
|----|---------|------|---------|
| **io** | stdin/stdout（读写流） | ✅ P2 做实（r8 基础传递 + 40-g 族文件） | 已在线 |
| **ffi** | 外部调用 + 外部内存（CPointer 线性令牌） | ✅ 设计冻结（G3——ffi-ownership-model.md） | 批次 I/J 实现窗口随 FFI 做实 |
| **net** | socket 连接/监听 | 纯设计候选（12 §2.4.5 Stage 2 行） | Stage 2 后段/Stage 3（依赖效应系统——D5） |
| **process** | 子进程 spawn/kill | 纯设计候选（同上） | Stage 3+（并发模型引入后） |
| **file** | 文件系统读写 | 设计候选 | Stage 2+（stdlib 完整化联动） |
| **time/random** | 时钟/熵源（非确定性源） | 设计候选（影响确定性编译口径） | Stage 3+（确定性语义联动裁定） |
| **eval-stage** | 代码执行权（`run`/多阶段拼接后的求值） | 设计候选（与 multistage 化学反应——§5.2） | Stage 2+ 多阶段做实时 |
| **compilation-service** | 编译器即服务的被服务面（不可信代码沙箱） | P1 预留位已有（13 §3.3） | Stage 3（LSP/服务化） |

### 4.2 令牌演算（模型层操作——现状只有 mint）

| 操作 | 语义 | 现状 | 引入窗口 |
|------|------|------|---------|
| **mint（铸造）** | 授权面构造令牌（pub(crate) 构造面控制） | ✅ 已做实（mint_read/write_token + IoGrant::from_requirements） | — |
| **attenuate（削弱）** | 派生只减不增权限的子令牌（如读写→只读） | ❌ 无位 | Stage 2 中段（net 族引入时） |
| **delegate（委托）** | 令牌线性传递给被调方（值传递即委托——现隐式存在） | ⚠️ 隐式（RefCell 线性近似承载） | Stage 2 令牌值化时显式化 |
| **revoke（撤销）** | 令牌失效（能力可撤销面） | ❌ 无位 | Stage 3（效应协调主题成熟后） |
| **compose（组合）** | 多令牌复合授权（grant 集合语义——现以 IoGrant 双字段近似） | ⚠️ 特化形态 | net/process 族引入时泛化 |
| **amplify（增强）** | 提权（受控面——仅组合根） | ❌ 无位（按设计**永不语言面暴露**——仅宿主） | 宿主侧保留 |

### 4.3 分层架构（裁定后的目标形态）

```
┌─ 模型层（capability_model.rs——本批次冻结 P3 骨架）
│   CapabilityModelFamily（族抽象形状）
│   TokenCalculus（演算操作形状——attenuate/revoke）
│   授权管线通用形状（声明提取→铸造→验证→消费 四段论）
├─ 族层（一族一文件——40-g 惯例）
│   capability_io.rs（io 族——第一实例，现状保持）
│   ffi 令牌（CPointer——ffi-ownership-model.md 冻结，实现随 FFI）
│   net.rs / process.rs / …（Stage 2+ 逐族增文件）
├─ 管线层（capability.rs 泛化路径——M2 迁移）
│   Grant（族无关授权集合）/ 验证引擎（数据驱动表已就位）
└─ 消费层（builtins 参数化——按族注册门控内置）
```

## 5. 化学反应矩阵（用户指令 ① 后半——与其他预留的组合面）

> 边界条件：D10（效应-能力正交）+ §11（接口隔离）——**所有反应
> 以「正交可组合、不合并接口」为前提**。下表「协同增益」列 = 组合
> 后超出二者各自能力的新能力面。

| # | 反应对 | 组合面 | 协同增益（化学反应产物） | 裁定 |
|---|-------|--------|------------------------|------|
| C1 | **能力 × 效应** | 通道权限（静态授权）× 控制流抽象（动态挂起） | ① perform 需能力令牌（效应执行=资源消耗→静态门控）② handler 安装=权限作用域（handle 体内令牌可见性）③ 能力可视为不可撤销的效应（12 §2.4.5 依赖表述——revoke 与效应恢复的统一语义窗口） | **D5：组合不合并**——效应系统不复制门控逻辑；能力模型不感知 handler；交点=令牌在 continuation 中的线性传递约束 |
| C2 | **能力 × 多阶段** | 权限静态性 × 代码值流动性 | ① `run`（未来阶段代码执行）= **eval-stage 能力门控**——quote 的代码携带「编译期已验证的能力集合」，splice/run 时按集合放行（代码值=可审计的权限容器）② 多阶段程序的能力审计 = 静态全阶段验证（比运行时检查更强） | **D6：代码值携带能力集合**——multistage 做实时按此口径；quote 面零改动（集合在 run 验证） |
| C3 | **能力 × 编译缓存** | 缓存键内容寻址 × 权限声明 | CacheKey 必须含 IoRequirements（能力不同的同源程序**不可共享缓存**——否则未声明程序经缓存获得已授权行为=缓存侧权限逃逸） | **D7：缓存键加能力面**——批次 I 做实缓存扩展时落地（现内存缓存单进程面风险为零，磁盘化前置条件） |
| C4 | **能力 × FFI** | 能力令牌 × 线性令牌（CPointer） | ① FFI 族=能力模型第二实例（B5——CPointer 语义即能力令牌：不可伪造+线性+一次性）② pin/unpin = 外部内存权限的授予/归还（Φ 计数簿=权限审计账）③ FfiCall 门控 = ffi 能力声明 + CPointer 线性消费双闸 | **D8：统一到模型层命名但冻结签名不动**——ffi-ownership-model.md 的 CPointer 契约按族实例归位；模型骨架（本批次）提供其类型归属 |
| C5 | **能力 × HM 类型** | 线性令牌 × 泛化（值限制 D2） | ① 能力令牌作为**一等值**进入类型系统：令牌类型=不可泛化类型（泛化=变元逃逸=权限扩散）——值限制（App 结果/set! 目标弱单态）天然阻止令牌泛化泄漏 ② 类型即权限文档：`(require io read)` 声明面 → HM 环境中令牌类型显式携带 | **D9：令牌类型禁泛化**——HM 旗标期切换时在 zonk 前拦截令牌类型变元（设计注记先行，实现绑定 HM 生产切换批次） |
| C6 | **能力 × 工具链/编译器即服务** | 不可信代码 × 编译服务 | 编译即服务面 = 能力沙箱的第一消费场景（被编译代码的 require 声明=服务合同；Grant 按合同铸造=最小权限执行）——13 §3.3 P1 预留位的行为面语义 | **D10b：服务面合同语义**——Stage 3 服务化时按本模型口径实现；本批次仅注记归位 |

**矩阵结论**：六条反应全部成立且**无一要求合并接口**——正交裁定
（D10/§11）在每个反应对上保持；化学反应的产物是「组合语义注记 +
交点约束条款」，不是新 trait 或合并模块。**这正是预留层拆分
（40-g）正确性的反向验证**：一族一文件的形态使每个反应对可以在
各自文件内独立演进、在模型层（新增骨架）统一锚定。

## 8. 测试锚点（Probe 契约 + 扩展面验证）

**正例（≥6）**：
1. `capability_model_skeleton_compiles`——族 trait 演算 trait 可编译（P3 契约冻结证明——40-g Probe 同型）；
2. `io_family_satisfies_model_family`——io 族实例类型满足模型族形状（**模型-实例归属证明**——本设计核心命题的机器验证）；
3. `ffi_token_satisfies_model_family`——CPointer 形状（编译期类型锚）满足族形状（D8 归位证明——ffi-ownership-model 契约的模型层归属）；
4. `calculus_shapes_have_stage2_slots`——attenuate/revoke 签名位存在且无实现体（预留位证明）；
5. `reserved_paths_still_valid`——`crate::reserved::ReadCapability` 等既有路径经 re-export 恒有效（M1 零破坏实证）；
6. `existing_io_tests_unchanged`——capability.rs 既有 12 测试零改动通过（原则 27 兼容实证）。

**负例（≥6）**：
1. 令牌不可构造（外部 crate 无 mint 面——私有构造编译期证明，既有测试维持）；
2. 演算 trait 无默认实现滥用（P3 位不可被实现体污染——探针断言形状）；
3. 模型骨架不引入 IO 专属名（命名审计——模型层禁 `Io` 前缀，防层次再耦合）；
4. 族抽象不吞族契约（`CapabilityModelFamily` 不含 read_line/write_line——接口隔离证明）；
5. Probe 不依赖运行时（纯类型级——P3 无运行时语义纪律）；
6. 预留计数不漂移（13 §3.3 14 项计数不受影响——文档断言注记）。
