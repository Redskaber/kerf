## 1. 定位声明

本文档是 [stage-2/plan §1](./plan.md) §21.3 阻塞项的先行裁定产物：**FFI 所有权模型未定义 → 批次 G3 先行定义**（GC pin/unpin 边界 + 线性令牌跨 FFI 边界的语义裁定——13 §3.3.4 冻结规格的行为补全），实现随后。

为什么所有权模型是 FFI 做实（§21.3 验收条件 4「ExternalType/FfiCall/FfiBoundary 按冻结契约做实」）的前置：

1. **冻结的只是形状，不是行为**：13 §3.3.4 冻结了 `ExternalType`/`FfiCall`/`FfiBoundary` 的类型签名，但「谁分配、谁释放、跨边界时对象归属」全部留白；13 §4 将「FFI 所有权模型」列为三个待定决策之一，预期解决时机正是 Stage 2。
2. **不做裁定即悬垂**：`CallExternal` 把 GC 堆对象的裸指针传出边界后，若无 pin 协议语义，任何一轮 mark-sweep（[05-运行时 §4](../../lang-design/05-runtime.md)）都可能回收该对象——根集完备性不变式（五来源）被破坏 = 悬垂指针 = P0 级安全缺陷。
3. **错误面必须闭合**：外部释放后使用、双重释放等终态若不裁定为诊断错误，就落成 UB——与 [06-操作语义 §3](../../lang-design/06-operational-semantics.md)「无未定义行为」的全集覆盖口径冲突。

**边界约束（本文档自誓）**：只裁定行为语义，不改任何冻结类型形状——`ExternalType`/`FfiCall`/`FfiBoundary` 签名逐字保持 13 §3.3.4 原状；`pin_object`/`unpin_object` 的调用方、时机、计数语义属行为面，正是本文件的裁定对象。

## 2. 问题空间：三原语所有权责任矩阵

| 原语 | 分配方 | 释放责任方 | 跨边界归属 | 生命周期机制 |
|------|--------|-----------|-----------|-------------|
| `CallExternal` | C 函数内部自决 | 按返回类型三分（§2.1 表） | 实参 = 调用窗口**借用**；返回值 = 按类型三分归属 | pin 窗口自动配对（§3 窗口规程） |
| `AllocExternal` | 外部 malloc 域（**不经过 GC**——冻结注记） | kerf 侧（经 `FreeExternal` 显式释放） | kerf 持有线性所有权（`CPointer` 令牌） | 线性令牌一次性消费（§4/§5） |
| `FreeExternal` | —（释放原语） | kerf 触发、外部 free 执行 | 令牌消费失效、外部内存归还 C 堆 | 状态机 `Invalid` 终态（§5） |

### 2.1 CallExternal（调用外部函数）

**参数方向（kerf → C）**：按实参类型分派——

- `CInt` 实参：值拷贝出界，无生命周期交互；
- `CPointer` 实参：只接受 Foreign 值（`AllocExternal` 产物或外部返回的令牌——Invalid 令牌传参 = E9 诊断）；kerf 堆对象数据指针（如 `Str` 缓冲，批次 I print 路径）出界的**唯一合法形式 = 调用窗口借用**，由边界包装自动 pin/unpin 配对（§3 窗口规程四步）。

**窗口规程（编译目标码序，边界包装层执行）**：

1. 实参求值（求值期间对象靠 VM 栈根存活——根集来源 1）；
2. 装载边界：堆实参逐个 pin（`Φ[v] += 1`）；令牌实参校验有效性（Invalid → E9）；
3. 发起 C 调用（VM 挂起——见 §6 case 6）；
4. 返回：按 return_type 包装返回值（不依赖实参堆对象存活——见信任边界注记）；全部堆实参 unpin（`Φ[v] −= 1`）。

**返回方向（C → kerf）三分法**：

| return_type | kerf 域形态 | 所有权裁定 |
|-------------|------------|-----------|
| `CInt` | 装箱 `Int`（GC 域，`alloc_int` 八入口之一） | 值拷贝，kerf 全权（GC 管理） |
| `CPointer` | Foreign 令牌（`HeapObj::Foreign` 承载——TD-010 既定方向，[05-运行时 §3.1](../../lang-design/05-runtime.md)） | **所有权移交 kerf**：可经 `FreeExternal` 释放（strdup 类惯例：C 分配、kerf 持有、kerf 释放） |
| `Opaque` | Foreign 令牌（同上） | **外部持有**：kerf 不可释放（`FreeExternal` 对 Opaque = E10），生命周期由外部 API 约定（fclose/fopen 类） |
| `CStruct` | 逐字段递归三分（标量拷贝装箱 / 指针字段独立令牌化） | 字段各自归属；按值传递 = 深拷贝语义，不引入 struct 句柄 |
| `CFunction` | Stage 2 不消费（P3 形状冻结——语言面无函数指针落地通路） | — |

**C 返回 NULL（哨兵惯例）**：NULL 值 `CPointer` 令牌 = `Valid` 态空令牌——`FreeExternal` 为合法 no-op（对齐 C `free(NULL)` 定义良好）；解引用 = E9（零地址并入令牌违规）。

### 2.2 AllocExternal（分配外部内存）

- 产出 `CPointer` 令牌，分配走外部 malloc 域——**不经过 GC**（13 §3.3.4 冻结注记 + ffi.rs「显式生命周期」注记）；GC 只管理承载它的 `Foreign` 堆槽，**不追踪**令牌载荷（ffi.rs 注记 3 同口径）。
- `size: usize` 是静态字段 → `size = 0` 可静态判定，**编译期诊断拒绝**（§6 case 4）。
- 释放唯一通路 = `FreeExternal`；承载 Foreign 槽被 GC 回收而令牌未消费 → 外部内存**泄漏**（容忍口径见 §6 case 9）。

### 2.3 FreeExternal（释放外部内存）

- `ptr: CoreExpr` 求值结果必须为 Foreign 令牌——非 Foreign 值（任意 kerf 堆/直接值）= E10（编译期类型前置检查锚定批次 G2 HM 之后）；
- 仅可释放 `CPointer` 令牌——`Opaque` 令牌 = E10（外部所有权，kerf 侧无释放权）；
- **消费语义**：槽级失效标记全局生效（所有共享该令牌的绑定同时失效，§4）；双重释放 → E9（§6 case 5）。

## 3. GC pin/unpin 跨边界语义（形式化规格）

**计数簿 Φ**：扩展 [06-操作语义 §1.2](../../lang-design/06-operational-semantics.md) 的 `σ = (H, R)` 为 `σ = (H, R, Φ)`，其中 `Φ: GcRef → ℕ` 是 pin 计数簿（根集第五来源「外部登记引用」的计数化泛化——[05-运行时 §3.2](../../lang-design/05-runtime.md)）。`foreign_roots = supp(Φ) = {r | Φ(r) > 0}`。

**归约规则**（P/U 族，与 R1-R9 同层补充）：

```text
(P1)  ⟨pin(v), ρ, (H,R,Φ)⟩ → ⟨unit, ρ, (H,R,Φ[v↦Φ(v)+1])⟩      v ∈ H（堆值：计数 +1）
(P2)  ⟨pin(v), ρ, (H,R,Φ)⟩ → ⟨unit, ρ, (H,R,Φ)⟩                 v ∉ H（非堆值：no-op，幂等）
(U1)  ⟨unpin(v), ρ, (H,R,Φ)⟩ → ⟨unit, ρ, (H,R,Φ[v↦Φ(v)−1])⟩     Φ(v) > 0
(U2)  ⟨unpin(v), ρ, (H,R,Φ)⟩ → Err(ε-E8)                        Φ(v) = 0 ∧ v ∈ H（簿记下溢）
```

- **可重复 pin 同一对象**：计数累计（3 次 pin → 计数 3，需 3 次 unpin 才摘根）——引计数式屏障（ffi.rs 行为注记 1 同口径）。
- **pin 集合进入根集的确切时机**：回收周期 `mark_all` 起点**快照并入**（[05-运行时 §4](../../lang-design/05-runtime.md) 伪代码 `work.extend(heap.foreign_roots())` 的既有行为，本模型不改）；GC 周期原子执行（单线程域），周期中途不存在 pin/unpin 插入。
- **unpin 到 0 的回收资格**：仅从 `supp(Φ)` 摘除 → 对象**下一轮**回收周期可回收（若无其他根）——不是立即回收；与 mark-sweep 的语义时序一致。
- **与 mark-sweep 主循环的交互**：pin 对象每轮从 `supp(Φ)` 可达 → 被标记 → sweep 保留；标记位每轮复位对称（05 §4 不变式 2）不受 Φ 影响——**Φ 独立于标记位持久**（标记位是周期态，Φ 是程序态）。
- **pin 非堆值（Nil/Int 直接量）**：no-op（P2）——pin 的契约是「保证不被回收」，非堆值恒满足契约；幂等性允许边界包装「无差别 pin 全部实参」的统一循环（不逐值判堆）。
- **unpin 下溢**：归 [06-操作语义 §3](../../lang-design/06-operational-semantics.md) E8 口径（内部不变式破坏 = 边界实现缺陷，P0 级编译器质量问题，非用户错误）——pin/unpin 由边界包装**结构性配对**调用，用户程序无法触达不配对状态。

**引理 F-PIN（pin 存活保证）**：若回收周期起点 `Φ(v) ≥ 1`，则本轮 sweep 不回收 v。证明：mark 从 `supp(Φ)` 出发 → v 被标记 → sweep 仅回收未标记槽（05 §4 三阶段骨架）。这是 05 §3.2 根集完备性不变式（五来源缺一不可）在 FFI 面的直接泛化。

**L-GC 保持声明**：pin/unpin 是经 FFI 原语边界包装发出的**程序可观测语义操作**（出现在 P/U 归约规则中，同 δ 地位），不是 GC 内部时机；[06-操作语义 §4](../../lang-design/06-operational-semantics.md) L-GC（GC 触发点不影响归约结果）无需修改——根集完备性经 `supp(Φ)` 并入第五来源维持。

**窗口承诺与防御性定位**：Stage 2 单线程非增量 GC 下，`CallExternal` 窗口内 VM 挂起、GC 不运行——pin 窗口因此是**防御性正确性协议**：(1) 它是「外部借用指针有效期」的规范定义（窗口内 Φ ≥ 1 ⟹ F-PIN 存活保证；窗口外 kerf 不作任何承诺）；(2) 它保证演进到分代/增量/并发 GC（05 §3.1 既登记方向、TD-008）时 FFI 语义零改动（窗口内保活由 Φ 机制结构性维持）。Stage 2 若省略 pin（依赖「窗口内无 GC」的实现巧合），演进即破坏——依据 sop §2.3-1（长期 > 短期）。

**pin/unpin 不入语言面**：`FfiCall` 三原语（13 §3.3.4 冻结）即语言面 FFI 原语全集；`pin_object`/`unpin_object` 是 `FfiBoundary` 的**实现协议**（调用方 = FFI 边界包装层），用户程序不可直接表达——不增补语言原语即不触碰冻结形状。

**深/浅 pin 的消解**：pin 是**根集操作**（单点追加 supp(Φ)），不是可达性操作——从 pin 点出发的整个可达子图由 mark 阶段自然传播覆盖。因此「深 pin vs 浅 pin」是伪问题：**浅 pin（单点）在 mark-sweep 下语义等价深 pin（全图）**（§6 case 8 同口径裁定）。

## 4. 线性令牌（Linear Token）语义裁定

**主裁定**：`ExternalPointer` 令牌 = **可重复借用传递 + 一次性消费（消费全局生效）**——传递与共享不改变令牌状态；消费（`FreeExternal`）经槽级失效标记全局生效，令一切共享引用同步失效。

**为什么以「消费全局生效」而非「类型系统防复制」实现线性性**：

1. kerf 值语义天然共享（`GcRef` 句柄可被多处 Value 引用、`set!` 可多处绑定）——防复制需要类型级线性检查，超出 Stage 2 HM 推断范围（线性类型完整化是演进议题，13 附录 next2 对照口径）；
2. 线性性的**安全目标**（防双重释放、防用后释放）不依赖防复制——消费全局失效即达成同一安全边界；
3. 防复制会同时禁止合法的借用共享（同一缓冲多处传参），收益为负。

**令牌失效的检测边界（诚实条款）**：

- **kerf 可簿记的释放**（`FreeExternal` 消费）：失效后任何使用（传参/解引用/再释放）= **诊断错误 E9，而非 UB**——这是「无未定义行为」口径（06 §3）在 FFI 面的强制延伸；
- **外部侧释放**（C 侧 fclose 后 kerf 再用 Opaque 令牌）：kerf **不可检测、不可防御**——显式声明为**信任边界条款**：kerf 语义域内无 UB 的承诺不覆盖外部域违约（C 代码违反借用/所有权约定属外部契约问题，同 06 §3 E8 之于编译器质量边界的分层逻辑）。失效通知协议（外部回调 kerf 失效钩子）= Stage 3 锚。

**与 hygiene/作用域集机制的协同**：

- `CallExternal` 的 `symbol: Symbol` 解析自 **extern 符号表**（独立于用户词法环境的扁平符号空间）——不可被 `define`/`set!` 遮蔽，宏卫生不穿透 FFI 符号空间（extern 声明的语言面形式由批次 G1/I 定义，本文只裁定解析域独立性）；
- Foreign 令牌作为普通值流动：`VarRef`/`SetBang` 的引用/绑定作用域集元数据（r13 TD-004 字段）跟随一般值规则，**无 FFI 特例**——依据 sop §2.3-6（通用 > 特例）。

## 5. ExternalPointer 生命周期状态机

**状态集**：`Valid`（有效：可传递/可解引用/可释放）→ `Invalid`（已消费：任何 FFI 原语操作 = 诊断吸收态）。外部侧释放不可观测，**不入状态机**（信任边界，§4）。

```text
[创建]  AllocExternal / CallExternal 返回 CPointer/Opaque ──▶ Valid
Valid ── 借用传递（CallExternal 实参）──▶ Valid          （自环：不消费）
Valid ── 解引用（经 FFI 读面）─────────▶ Valid          （自环：不消费）
Valid ── FreeExternal（仅 CPointer）────▶ Invalid       （一次性消费，不可逆）
Invalid ── 任何 FFI 原语操作 ──────────▶ Err(E9)        （吸收态）
Opaque 令牌：不存在 kerf 侧消费通路（恒 Valid——直至承载槽被 GC 回收，见 §6 case 9）
```

**非法状态迁移表**（每条附诊断码建议）：

| # | 起态 | 操作 | 判定 | 诊断码建议 |
|---|------|------|------|-----------|
| 1 | `Invalid` | `FreeExternal` | 双重释放 | E9（令牌失效） |
| 2 | `Invalid` | 传参 `CallExternal` | 用后传递 | E9 |
| 3 | `Invalid` | 解引用 | 用后使用 | E9 |
| 4 | `Valid` | `FreeExternal`（Opaque 令牌） | 所有权违规：外部持有不可释放 | E10 |
| 5 | `Valid` | `FreeExternal`（非 Foreign 值） | 类型违规：非令牌不可释放 | E10 |
| 6 | 任意 | `CallExternal` 符号未解析 | 链接/加载失败 | E11 |
| 7 | — | `unpin` 计数下溢 | 边界实现簿记缺陷 | E8（06 §3 既有口径，P0 缺陷） |

**诊断码族建议（回写义务）**：E9 `FfiTokenInvalid`（令牌失效后使用）、E10 `FfiOwnershipViolation`（所有权/类型违规）、E11 `FfiSymbolResolution`（符号解析失败）——延续 [06-操作语义 §3](../../lang-design/06-operational-semantics.md) E 族编号；实现落地轮按 sop §8.4.5 规则 3 回写 06 §3（E0–E7 全集覆盖声明随之扩为 E0–E11）。

## 6. 边界 case 清单（13 个场景，每个附规格判定）

| # | 场景 | 规格判定 | 依据 |
|---|------|---------|------|
| 1 | pin 后 GC 运行（窗口内周期） | `supp(Φ)` 并入 mark 起点（F-PIN）→ 对象存活；`GcRef` 是 u32 句柄 + slot-Vec 非移动（05 §3.1/§4 冻结口径）→ C 侧裸指针窗口内稳定 | 05 §3.1 / §4 不变式 1 |
| 2 | pin 期间 kerf 侧 `set!` 修改对象 | 允许——pin 只约束回收资格，不冻结内容；单线程域内 VM 挂起与 C 读取天然互斥，无数据竞争 | 本模型新裁定（Stage 2 单线程前提，13 §4 并发 Stage 3） |
| 3 | 外部回调持有指针（越过窗口） | Stage 2 语言面**无回调通路**（`CFunction` 是类型形状非回调注册面）；借用指针窗口外失效，C 违约持有 = 信任边界外行为；回调语言面 = Stage 3 锚 | 13 §3.3.4 + 本模型新裁定 |
| 4 | `AllocExternal` size 为 0 | **编译期诊断拒绝**（size 是静态字段，可静态判定；零尺寸缓冲在 kerf 请求面无合法用例）——防御纵深：运行期令牌仍拒绝任何解引用（E9） | sop §2.3-4（报错 > 静默）+ 本模型新裁定 |
| 5 | `FreeExternal` 双重释放 | 第二次释放时令牌已 `Invalid` → E9 诊断吸收，**不是 UB**（对齐 C double-free 的 UB 语义升级为诊断） | 06 §3 无 UB 口径 + 本模型新裁定 |
| 6 | `CallExternal` 期间 GC 触发 | **不触发**——GC 触发 = 分配计数超阈 + VM 安全点轮询（05 §3.1/§4 陷阱 2），外部调用期间 VM 挂起即无轮询点；外部 malloc 不进 kerf 分配计数；返回值装箱（`alloc_int`）的触发点在 unpin 之后、且返回值不依赖实参堆对象（§2.1 窗口规程步 4） | 05 §3.1 分配触发协议 + 本模型新裁定（时序裁定） |
| 7 | 返回 `Opaque` 类型到 kerf 域 | Foreign 堆槽装箱（`HeapObj::Foreign` 承载——TD-010 既定方向）；不可 `FreeExternal`（E10）、不可解引用（无 PointeeType），只能整体借用传回外部函数 | 05 §3.1 TD-010 + 13 §3.3.4「不可构造」 |

| 11 | 令牌复制后一处 `FreeExternal` | 消费全局生效（槽级失效）→ 所有共享绑定同步失效，任何一处后续使用 = E9；GC 回收承载槽不消费令牌（§4 主裁定的运行时形态） | 本模型新裁定 |

## 8. 实现路线（G1 PoC 如何消费本模型）

- **批次 G1（QBE 后端 PoC）**：fib/exit code 整数路径 = `CInt`-only `CallExternal`——无堆实参 → pin 退化为空循环（`Φ` 不动），**不触及** pin/令牌/状态机；PoC 验证的是 `FfiCall` 的 IR 表示、C ABI 调用约定与 E11 符号解析路径。依据 [stage-2/plan §5](./plan.md) 批次 G 节点序（G3 定义 → G1 PoC → G2 推断）。
- **批次 I（print/IO FFI 面做实）**：`write_stdout(char* buf)` 路径按本模型落地——`Str` 堆槽 pin（窗口规程步 2）+ 数据指针借用出界 + 返回后 unpin（步 4）；`AllocExternal`/`FreeExternal` 面开放（含 E9/E10 诊断与状态机失效标记）；`HeapObj::Foreign` 变体落地（TD-010 偿还）。
- **批次 G2（HM 推入）**：`FreeExternal` 实参的 Foreign 类型前置检查（case 12 的类型级升级）。
- **回写义务（sop §8.4.5 规则 3，落地轮执行）**：06 §3 补 E9–E11 三终态；05 §3.1 补 `HeapObj::Foreign` 变体注记；13 §3.3.4 行为规格处加本文引用；TD-010 登记册状态更新。
