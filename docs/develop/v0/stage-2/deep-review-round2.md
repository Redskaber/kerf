## 2. 八维度审查结论

### D1. 架构健康度

- **现状**：10 crates 五正交轴分层（15-架构分层 L0-L4）维持健壮。§11 接口隔离七项机械验证**全过**（57-s1 实测）：compiler→reader 引用 = 0（Cargo.toml 依赖仅 span/syntax/core）；vm→compiler = 数据类型 only（BcConst/BcProgram/Op/CaptureSource——正当输入格式引用，编译期测试专用引用位于 cfg(test)）；compiler→driver = 代码 0（2 处 doc 归属注记非依赖）；**reader 生产调用者 = driver 唯一**（driver.rs:20 / bootstrap.rs:27 / bootstrap_expander.rs:577 / bootstrap_compiler.rs:886——种子 parity 桥与类型转换，均为组合根职责）。生产路径单向流：driver → reader → expander → core → compiler → vm → runtime（r23/INC7 eval 退役后 VM 唯一生产执行路径，互查口径 = 生产链 vs 种子链 run_source_seed）。耦合计数：vm↔runtime 经 ForeignBox tracer 协议（§11 隔离设计——kerf-runtime 不依赖 kerf-vm 类型），backend QBE 独立 crate，三扩展槽帧（ext1 = HandlerFrame r25 具体化）结构收敛。
- **风险**：无新增跨阶段耦合。潜在观察项：hm.rs（1087 行）/ vm.rs（2266 行）/ anf.rs（819 行）单文件体量——TD-012 先例（expander.rs 拆分六文件）证明可拆，但当前内聚度合理（编译/HM/执行各为单一职责域），**不构成重构必要项**（§14.8.3 条款 5：可重构 ≠ 立即重构）。
