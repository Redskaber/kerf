## 3. 自举 parity 链保护方案（入口信号④的评审对象）

### 3.1 parity 三门体系复用（单源 = i1-incision-migration-design §5）

E5 窗全程复用 i1 切口设计的既立三门（零新造门——§2.3 原则 6「通用 > 特例」）：

| 门 | 判据 | E5 适用性 |
|---|---|---|
| **门 A（段 parity）** | 同一 CoreExpr 输入：`bytecode_equal(seed_out, bootstrap_out)` 全结构含 debug_spans | S2/S3 腿核心（关键字切换与结构重构的零语义漂移段证明）；S1 腿自动覆盖（注册面变更不改编译段） |
| **门 B（自举一致性 = §21.3 条件 2）** | 自举链两次编译自身：B₁/B₂ 四程序（reader/expander/compiler/preamble）bytecode_equal + SHA-256 一致 | **三腿全适用**——每腿语料迁移后 B₁/B₂ 自一致必须重建（语料变更自身合法，但 fixpoint 性质不变）；加强判据 B₀ vs B₁（种子-自举全链 parity）同持 |
| **门 C（回归门）** | 全套件零回归 + 审计集 EXIT 0 + T1 双路径 + CLI 冒烟 | 三腿收尾统一（§3.2 六命令 = 门 C 的执行化） |

### 3.2 每腿 parity 断言矩阵（分步验收——23 §2.3 红线 4）

> 红线 4 原文：「E5 窗内的多重构**同窗但分步验收**（每步 parity 断言先行）」。

| 腿 | 迁移前快照（断言基准） | 迁移后断言（验收门） | 语义漂移证明形态 |
|---|---|---|---|
| **S1 表面腿** | ①837 全套件基线（r41 终态）②B₁/B₂ fixpoint 基线（SHA 记录）③`BUILTIN_ALIASES` 27 对映射表（单源） | ①全套件零行为回归（**测试随语料迁移，断言值不变**——迁移是文本替换 + 名面退役，行为面 = 同一分派体同诊断的历史 parity 锚定 r38）②B₁'/B₂' fixpoint 重建（新语料自一致）③旧名 27 件零注册（计数锚 84→57）+ 语料旧名零引用（grep 实证）④**E0021 负例组**（旧名 → E0021 携现代名指引——「移除 = E 级错误 + 负例组」20 §7 出口口径）⑤W1003 正负例（宏名遮蔽内置 → W 级知会） | **行为 parity**（r38 别名层已证同分派体同诊断——S1 只是把「双名同行为」收敛为「独名 + 旧名拒绝」） |
| **S2 关键字腿** | ①S1 终态全套件基线②门 A 语料 CoreExpr 基线（关键字切换前） | ①门 A：同一源经新关键字表产**相同 CoreExpr**（`fn` 与 `lambda` 同映 `CoreExpr::Lambda`——表面/内部分离原则 31 的直接断言）②门 B fixpoint 重建③关键字切换负例组（`lambda` 旧形 → E0021 族同型错误携新形指引）④全套件零行为回归 | **CoreExpr parity**（骨架不变断言——02 §1 表面可替换的机器验证） |
| **S3 ADT 腿** | ①S2 终态全套件基线②**字节码快照**（结构重构前的 B₁ 全程序 bytecode——零漂移证明的对照组） | ①**字节码全等**：`Define` 脱糖/`Begin→Let` 后同一源产 bytecode_equal(重构前, 重构后)（M-D/M-A 的零语义漂移**硬证明**——脱糖是语义保持变换）②门 A/B/C 全套③`Define`/`Begin` 非正交点消除复核（21 §5.5 计数 3→1）④全套件 + 审计 + CLI | **字节码 parity**（最严口径——结构重构的唯一合法漂移 = 零漂移） |

### 3.3 风险与回退

| 风险 | 缓解 | 回退 |
|---|---|---|
| 语料迁移引入文本误替换（`car` 命中标识符子串） | 词法边界替换（`\b` 级正则 + 迁移后 grep 零旧名实证 + 全套件零回归双保险） | 单 commit 回退（git 436a2b9 基线） |
| S1 移除后引导链断裂（.krf 残留旧名 → 未绑定） | 迁移先行 + 种子链自检（`compile_source_seed` 全 .krf 过）+ 门 B fixpoint | 同上 |
| W1001 退役误删 W1002（同族相邻实现） | 分函数退役 + W1002 专测在位（M2 既有锚不动） | 同上 |
| S3 字节码不等（脱糖实现漂移） | 门 A 段 parity 前置（每臂单独 bytecode_equal）——不等即 P0 停线 | 分臂回退（结构重构按臂独立 commit） |

### 4.1 S1 腿内部 MUV 序（本轮 63-b）

1. **码位预登记**（18 §6 纪律：先占位后落位）：E0021（移除名错误）+ W1003（宏名遮蔽警告）

3. **E0021 落地**：driver 绑定检查处——旧名引用（值位/操作位）→ E0021「已于 v0.9 移除，现代名 X」（fail-closed；比 E0004 未绑定更 actionable——20 §7「旧名引用 = E00xx 错误」兑现）
4. **W1001 退役**：弃用族收集逻辑删除（错误已升 E 级——W 级面消失合法）+ preamble 豁免机制随之退役（preamble 本体已迁移）
5. **W1003 落地**：`define-syntax` 宏名 ∈ 内置注册面（57+47 名）→ W 级知会（22 §11 D11：宏胜出是本质能力，遮蔽内置值得知会——W 级唯一可判定位）
6. **语料迁移**：bootstrap ×4（compiler/expander/reader/preamble .krf——词法边界替换 27 名）+ tests ~394 处 + examples + audits
7. **负例/正例组**：E0021 ≥8 case（值位/操作位/限定形/恢复健康）+ W1003 ≥3 case（正例知会 + 非内置名零误报 + 定义后正常调用）+ 旧名负例组端到端
8. **守卫扩展**：注册计数锚 84→57 断言 + REMOVED 表闭合守卫（27 对双向对账）+ 门控六名 ⊆ 注册维持

### 4.2 `?`/`->` 词法域收紧裁定（20 §7「可选」的裁决）

**维持不收紧**（本轮裁定）：`?`/`->` 仍为合法标识符字符——判据：①kerf 自身引导私有名（`str->pos-chars` 等四件 Reader 服务）仍持 `->` 形态（M1 注记：引导私有不入用户面——词法域收紧将强制改私有名，收益边际）；②用户自定义 `?`/`->` 名的合法性是 N0 符号宇宙层自由（收紧 = 无判据的家族模仿——原则 35 反锚定：Clojure 的宽松不是权威，Rust 的收紧也不是）；③现代名规范 R2/R4（`is-`/`-to-`）由 20 §5 命名检查承载（新名纪律），无需词法强制。**否决记录保留**：若后续生态（包管理窗口）出现 `?`/`->` 名冲突实证，重评条件成熟。
