## 3. 管道流程审查

### 3.1 单向 DAG 实证（无回流/回查反模式）

- **cargo tree 实测**（2026-09-10）：拓扑序 `{span, runtime} → syntax → {core, reader} → {expander, compiler} → vm → driver → 根`，无反向边、无环；唯一"越级"是根 crate 引 `kerf_core::CodeValue`（CLI `code` 分析子命令，经 compile_source 产物消费，不触碰 reader/expander 内部——不构成回流）。
- **数据流方向**：source → tokens → Stx → CoreExpr → BcProgram → Value，每级只读下一级的**公共 API**（§11 隔离）；错误沿 Result 反向传播是控制流而非数据回流（错误消息携带 Span 前向信息，无需回查源文本结构）。
- **无"重推导"**：作用域集、捕获描述符、debug_spans、常量池索引全部在编译期一次性预计算（§14.7.2"元数据预计算"项 PASS）——VM 运行时零结构性回查。

### 3.2 中间表示必要性（四级各有消费者）

| IR 级 | 生产者 | 消费者（实证） | 判定 |
|---|---|---|---|
| Stx（语法对象） | reader | expander `expand_form`（宏匹配输入）；CLI `stx` 子命令 dump | 必要——宏系统需要 datum+scope 的相位载体 |
| CoreExpr（9 原语树） | expander | compiler `compile_module`（compile.rs:170 入口签名）；vm `eval_program`（双路径验证的参考实现）；CodeValue 良构性/自由变量分析 | 必要——编译与求值双路径共同消费，T1 定理的对照面 |
| IrGraph（图 IR） | core `lower_program` | CodeValue::from_expr（code_value.rs:58 内部 lower——自由变量收集/α 重命名/组合预留的载体）；CLI `ir` 子命令 dump（driver.rs:208 存入 CompileOutput） | **有条件必要**——见下方观察项 O-1 |
| BcProgram（字节码） | compiler | vm `run_program`（生产执行）；CLI `bc` 子命令 dump；`bench`（编译+执行整程） | 必要——VM 唯一执行输入 |

**判定：无"多余 IR"**——四级均有至少一个独立消费者，且 Stx/CoreExpr/Bc 三级的必要性由宏系统/双路径定理/VM 架构分别锚定。

**观察项 O-1（P3，效率）**：IrGraph 在 **run/eval 生产路径**上由 `compile_source`（driver.rs:208）无条件计算后旁路丢弃（`run_source` 只取 table/program/source_map/registry，不消费 `out.ir`；CodeValue 自行独立 lower）。成本为单遍 O(n)，fib.krf 级别实测不可感知，但严格口径下属于"生产路径上的分析旁路"。**定性**：IrGraph 是"分析 IR + Stage 2 优化预留（node_map 字面量共享/find_shared）"，非编译必经级——与其说是多余 IR，不如说是**落位时机**问题。**候选动作**（不在本轮执行，本审查仅登记）：①延迟化——`CompileOutput.ir` 改 `Option`/按需 lower（`ir`/`code` 子命令触发）；②或保持现状但把 driver.rs:211 注释"图 IR 源（CoreExpr 树）→字节码"更正为"并行分析 IR（编译输入为 CoreExpr 树）"消除歧义。两项均为小改动，建议随 TD-012 同批在 §13.2 切换期处理。

### 3.3 流程级结论

✅ 管道数据流为单向 DAG 无回流反模式；✅ 中间表示四级各有消费者、无多余级；⚠️ 1 项 P3 观察项（O-1 IR 旁路计算）——不构成回归，已给出两个候选处置并建议登记。
