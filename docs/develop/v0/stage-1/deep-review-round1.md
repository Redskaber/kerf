### D1. 架构健康度（§11 接口隔离）

- **现状**：10 编译单元（9 成员 crate + 根 CLI）依赖实测 **DAG 无环**：`{span, runtime} ← syntax ← {core, reader} ← {expander, compiler, vm} ← driver ← 根`；driver 为唯一组合根（唯一全依赖成员），vm→compiler 四处引用全为数据类型（vm.rs:23 `use kerf_compiler::{BcConst, BcProgram, Op}` + 482/487 `CaptureSource` 模式匹配；vm.rs:866 在 `#[cfg(test)]` 内）。§14.7.2 清单实测：B1 compiler→reader **0** ✓ / B2 vm→compiler 内部 0（数据类型除外口径）✓ / B3 compiler→driver **0** ✓ / B4 根 CLI 直调 reader **0**（Stage 0 深审 A4 修复后的 driver 转发在位）✓ / B5 glob re-export **0** ✓。规模：Rust 18,056 LOC（66 文件）+ 自举 kerf 1,948 LOC（reader 471 / expander ~1,180 / preamble 297）+ 测试 7,568 LOC（25 文件）；最大文件 vm.rs 1,526 / builtins.rs 1,473 / driver.rs 1,053——**无单文件超 1,600 失控线**（Stage 0 深审 D1 风险②的 TD-012 expander.rs 1,350 已随批次 B 前端重写拆解为 6 文件、最大 715）。
- **风险**：① catch-all（`_ =>`）从 Stage 0 r1 的 42 处降至 **15 处**（expander 前端重写的结构性收益），但仍有 **1 处无臂级注释**（36-c 清理项）；② 生产区 `.expect()` 4 处（expander.rs:247 / phase.rs:110/116/133）——均为「调用方已校验/上方已检查」不变式 expect，合法但属 §6.2.0 触发时机 3 的观察模式；③ 自举双层结构（种子 → VM 上 kerf）使 driver 内聚 bootstrap/bootstrap_expander 两模块（5168 LOC crate）——职责仍单一（管线编排 + 自举桥），Stage 2 编译器本体迁移时是第一个自然拆分候选。
